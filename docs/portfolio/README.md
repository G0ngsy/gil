# 길빛 포트폴리오 자료 모음

최종 갱신: 2026-11-11 · 초기 구현 대조: `73404ca`, 이후 구현은 누적 기록 참조

앱 완성 후 포트폴리오로 편집하기 위한 내부 자료다. 현재 구현과 검증 근거를 정리하며, 완성된 서비스 소개나 성과 보고서로 취급하지 않는다.

## 읽는 순서

1. [프로젝트 개요](project-overview.md): 해결하려는 문제, 설계 원칙, 구조와 다음 단계
2. [구현 현황](implementation.md): 기능별 구현/검증/미확인 범위와 코드
3. [핵심 문제 해결 사례](case-studies.md): 문제 → 선택 → 구현 → 검증 → 제한
4. [검증·화면 근거](evidence.md): 테스트 실행 범위, 캡처, 배포 기록, 추가 수집 자료
5. [작업별 누적 기록](work-log.md): 구현 이력과 앞으로 사용할 기록 양식

## 이슈 기록과의 역할

- `docs/issues/`: 당시 발견한 문제·원인·해결·결과를 남기는 상세 원본이다. 과거 상태를 포함하므로 현재 상태와 다를 수 있다.
- `docs/portfolio/`: 원본 이슈와 현재 코드를 연결해, 프로젝트의 문제 해결 과정과 구현 범위를 이해하기 쉽게 정리한다. 이슈 전체를 복사하지 않는다.
- `docs/validation-*.md`와 개별 검증 문서: 실행 조건과 결과의 근거다. 테스트 개수를 합산해 성과 수치로 만들지 않는다.
- `docs/previews/`: 과거 화면 자료다. 시안·가상 장치·배포 화면의 성격과 촬영 시점을 확인해 사용한다.

## 앞으로 갱신하는 방법

기능 구현·의미 있는 수정마다 해당 기능의 [구현 현황](implementation.md)을 수정하고 [누적 기록](work-log.md)에 한 항목을 추가한다. 설계 선택이나 재현 가능한 문제가 있으면 [문제 해결 사례](case-studies.md), 검증·캡처가 생기면 [근거 목록](evidence.md)도 갱신한다. 자세한 장애 과정은 이슈에 기록한 뒤 링크한다. 문서 정리만 한 작업도 범위와 확인 방법을 누적 기록에 남긴다.

기록에는 사용자 문제, 변경 이유, 실제 동작, 검증 방법/범위, 미확인 사항, 코드·이슈·커밋 링크를 포함한다. 미래 계획을 완료 기능으로 쓰거나, 측정하지 않은 사용성·정확도·시간 절감 수치를 만들지 않는다. 사용자 요청에 따라 AI 지원으로 구현·검증을 진행한 기록이므로, 최종 공개 시 본인의 기획·판단·검토와 AI 지원 범위를 직접 확인해 서술한다.

## 현재 공개 설명에 쓸 수 있는 범위

> 한지색 UI의 보행 길찾기 프로토타입으로, 시안·실제 검색용 데이터 흐름·GPS 테스트를 분리했다. 센서 권한과 자원 해제, 잘못된 위치 입력, 경로 진행 판정을 자동 테스트로 검증했으며 실제 API와 실외 보행 검증을 준비하고 있다.

‘AR 길찾기 완성’, ‘실제 경로 정확도 검증 완료’, ‘사용자 만족도 향상’은 현재 근거로 주장할 수 없다. 공개용 설명은 앱 완성 시 다시 작성한다.
