# 핵심 문제 해결 사례 초안

작성: 2026-11-09. 공개용 최종 원고가 아니라 코드·이슈 기반 사례 재료다. 측정된 사용자 효과는 아직 없으며 아래 ‘결과’는 동작 검증 결과다.

## 1. 시안과 실제 안내가 섞이지 않게 설계

**문제:** 고정된 520m·8분·회전 문구가 목적지나 현재 위치와 관계없이 보여 실제 길 안내로 오해될 수 있었다.

**선택과 구현:** 시안, 실제 검색용 흐름, 이동 검증 화면을 분리했다. 실제 모드에서는 제공사 응답을 검사하고 오류가 나면 예시 경로로 대신하지 않는다. 카메라 실영상에는 시안 화살표를 숨긴다. 직접 설정한 현장 경로도 직선 테스트 도식임을 표시한다.

**검증과 결과:** 모의 API의 거리·시간이 표시되는지, 키 미설정·조회 실패 시 고정 거리/회전이 나타나지 않는지 검사한다. 현장 테스트는 외부 경로 API를 호출하지 않는지 확인했다.

**트레이드오프/한계:** 모드 전환과 별도 검증 화면이 필요하지만, 미연동 상태를 완료처럼 보이지 않게 한다. 실제 검색과 GPS를 하나의 내비게이션으로 연결하는 작업은 남아 있다.

근거: [검색 이슈](../issues/2026-11-06-navigation.md), [카메라](../../src/CameraPreview.tsx), [현장 경로](../issues/2026-11-08-field-route.md), [검색 테스트](../../tests/browser/navigation.spec.ts)

## 2. 닫은 화면 뒤로 도착하는 센서 응답 처리

**문제:** 권한 창의 응답이 늦게 도착하거나 화면을 떠나도 카메라·GPS가 계속 켜질 수 있다. 시안의 화면 닫기를 안내 종료로 처리하면 안내로 돌아갈 수도 없었다.

**선택과 구현:** 시안에서는 화면과 진행 중 안내 상태를 분리했다. 센서는 별도 수명으로 관리하며 사용자 버튼에서 시작한다. 요청/세션 번호를 증가시켜 과거 응답을 무시하고, 카메라는 늦게 온 stream의 트랙도 즉시 종료한다. GPS는 watch와 수신 타이머를 해제한다. 탭 숨김 후 자동 재시작하지 않는다.

**검증과 결과:** 가상 카메라·위치 콜백으로 취소 뒤 응답, 오류, 탭 숨김, 종료, 재시작을 검사했다. 현장 경로 변경 시 기존 GPS 콜백이 새 경로를 덮지 않는 것도 확인했다.

**트레이드오프/한계:** 탭 복귀 시 사용자가 다시 시작해야 한다. 이 동작은 백그라운드 내비게이션 구현이 아니다. 가상 장치 테스트는 모바일 OS 권한 동작을 대신 검증하지 않는다.

근거: [닫기/종료 이슈](../issues/2026-11-06-close-guide.md), [카메라 검증](../validation-2026-11-06-camera.md), [GPS 훅](../../src/navigation/useGpsTracking.ts), [GPS 테스트](../../tests/browser/tracking.spec.ts)

## 3. GPS 오차로 단계·도착이 건너뛰는 문제

**문제:** 가까운 선분 하나만 고르면 교차/평행 경로에서 후반 단계로 이동할 수 있다. 목적지 좌표 한 번이 튀어 들어오면 도착으로 오판할 수도 있다.

**선택과 구현:** 위치를 각 경로 선분에 투영하고 이전 진행에 가까운 후보를 우선한다. 단절된 선분을 임의로 잇지 않는다. 수신 간격에 비해 큰 진행 변화는 거부하고 이탈/복귀에 서로 다른 거리 기준을 적용한다. 도착은 종점까지 거리와 오차를 함께 검사하고 두 번 연속 확인한다. 계산은 UI에서 분리했다.

**검증과 결과:** 동일 좌표열로 정상 이동·역방향·점프 후 복구·교차·평행·완전 중첩·이탈 복귀·도착 확인 취소를 재현한다. 지도 원과 이동 구간에도 거부된 좌표가 반영되지 않는지 브라우저에서 확인했다.

**트레이드오프/한계:** 완전히 겹친 왕복 구간은 GPS만으로 방향을 확정하기 어렵다. 보수적으로 진행을 유지해 안내가 지연될 수 있고 먼 이탈 후에는 재시작이 필요할 수 있다. 임계값은 현장에서 보정하지 않은 테스트 기준이다.

근거: [오판 보강 이슈](../issues/2026-11-08-gps-matching.md), [계산](../../shared/tracking.ts), [단위 테스트](../../tests/tracking.test.ts), [도식 이슈](../issues/2026-11-08-tracking-map.md)

### 2026-11-09 후속: 위치 진행과 바라보는 방향을 분리

휴대폰·경로 방위 비교를 별도 순수 함수로 추가해 모의값으로 검증했다. 각도 차가 분류 경계에 걸치면 오차 범위 때문에 확인 불가로 반환한다. 이는 GPS 위치만으로 사람이 바라보는 방향을 추측하지 않기 위한 선택이며, 초기 단계에서는 화면/실제 센서 연결 없이 계산부터 검증했다. 후속으로 [모의 방향 카드](../issues/2026-11-09-facing-card.md)를 앱에 연결하면서 유효 방향의 800ms 안정화와 확인 불가 즉시 숨김을 분리했다. 실제 센서 연결은 아직 없다. [계산·검증 범위](../issues/2026-11-09-facing-comparison.md)를 참고한다.

### 실제 센서 후속: 방위 기준과 오차를 확인하기 전에는 안내하지 않기

[실제 센서 테스트 연결](../issues/2026-11-09-heading-sensor.md)에서는 자북과 진북의 차이를 로컬 모델로 보정하고, 정확도나 자세를 확인할 수 없는 데이터는 방향으로 단정하지 않았다. 실제 GPS/방위 표본의 시각은 모의값처럼 갱신하지 않는다. 권한·해제 흐름은 이벤트 주입으로 검사하며, 실기기 정확도와 모든 브라우저 지원을 완료했다는 근거로 쓰지 않는다.

## 4. 최근 기록의 편의성과 홈 정보량 조정

**문제:** 처음에는 검색/목적지가 새로고침 후 사라졌고 고정 예시가 최근 기록처럼 보였다. 저장 기능을 추가한 뒤에는 홈에 전체 기록과 관리가 노출되어 스크롤이 길어졌다.

**선택과 구현:** 실제/예시 모드를 분리해 검색어와 목적지 ID·이름·주소만 기기에 저장한다. 각각 10개로 제한하고 중복을 최신순으로 정리한다. 홈에는 최근 목적지 1개만 보여주고 삭제와 전체 목록은 별도 화면에 둔다. 손상된 저장값과 저장/삭제 실패를 처리한다.

**검증과 결과:** 새로고침, 중복, 삭제 확인/취소, 저장 차단, 모드 분리, 홈 복귀 후 다음 기록 표시를 자동화했다. 과거 배포에서도 요약·상세·삭제를 확인한 기록이 있다.

**트레이드오프/한계:** 홈 정보량은 줄지만 오래된 기록은 상세 화면에서 찾아야 한다. 실제 사용자가 더 빠르게 목적지를 찾았다는 측정은 없다. 기기 저장은 계정 동기화가 아니며 브라우저 정책에 영향을 받는다.

근거: [기록 이슈](../issues/2026-11-06-history.md), [요약 이슈](../issues/2026-11-06-history-summary.md), [구현](../../src/history.ts), [배포 검증](../validation-2026-11-06-history-summary.md)

Vercel 첫 배포에서 로컬과 다른 ESM import 해석으로 설정 API가 500을 반환했고 `.js` 확장자 명시 후 재배포로 확인한 사례가 있다. [배포 이슈](../issues/2026-11-06-deployment.md)와 [검증](../deployment-validation.md)을 참고한다. 최종 포트폴리오에는 역할과 지원 직무에 맞는 사례를 골라 사용하며 모든 이슈를 나열하지 않는다.

## 2026-11-10 — 실제 지도·경로선 검증

준비된 SDK를 주입한 모의 테스트는 실제 부트스트랩의 document.write 문제를 놓쳤다. 실제 공급자 호출로 원인을 찾고 부트스트랩/본체 순차 로드 및 필수 생성자 검사를 적용했다. 성공 HTTP 상태만으로 지도 완료를 판단하지 않고 화면·타일·경로선까지 확인했다. 공급자 내부 자산 경로 변경은 남는 의존성이다. [상세 이슈](../issues/2026-11-10-tmap-map-loader.md).

## 2026-11-10 — 실제 경로 GPS 연결

테스트 모드에서 검증한 진행 계산과 GPS 세션 해제 로직을 실제 경로에 재사용했다. 수신 문구를 매개변수로 분리해 실제 화면에 예시 경로라고 표시되는 혼동을 방지했다. GPS 갱신마다 지도/경로 전체를 생성하는 대신 위치 마커를 별도 갱신해 지도의 사용자 조작을 유지한다. [상세 기록](../issues/2026-11-10-live-route-tracking.md).

## 2026-11-10 — 지도 키 공유 안내 정정(현재 정책)

과거 같은 키로 지도 동작을 확인했으나 공개 사용의 안전성은 검증하지 않았다. 로컬 지도 키를 비웠고 같은 서버 키의 지도 재사용을 실행/빌드에서 거부한다. 공식 공개 자료로 지도 전용 키·도메인/API 제한을 확인하지 못했으며 지원 여부는 공급자 답변이 필요하다. 이전 지도 기술 검증 기록과 현재 설정을 구분한다. 설정 검사 3개·빌드 및 서버 키의 dist 비포함 검사를 통과했다. [원인·근거·확인할 질문](../issues/2026-11-10-tmap-key-separation.md).
