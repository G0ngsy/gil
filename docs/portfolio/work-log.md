## 2026-11-09 — 포트폴리오 자료 기반 정리

- 사용자 문제: 구현 이슈가 여러 문서에 흩어져 있어 완성 후 프로젝트의 판단·기여·결과를 다시 복원하기 어렵다.
- 변경: 별도 자료 폴더에 개요·현황·문제 해결 사례·검증/화면 근거·누적 기록을 구성했다. 상세 이슈는 보존하고 링크했다.
- 설계 판단: 개발 로그와 최종 사례 재료를 분리한다. 완료/모의 검증/실기기 미확인/보류를 구분하고 현재 코드를 기준으로 과거 이슈를 해석한다.
- 확인: Markdown 6개 문서의 로컬 링크 117개와 참조 커밋 15개 존재 확인, `git diff --check` 통과. 제품 코드 변경이 없어 제품 테스트는 재실행하지 않았다.
- 미확인: 최신 원격 배포·실기기·사용자 조사·정량 성과·공개용 기여 범위는 새로 확인하지 않았다.
- 후속: 구현 작업마다 현황과 이 기록을 갱신하도록 루트 작업 규칙에 추가한다. 최종 결과의 커밋 ID는 Git 이력에서 이 문서 추가 커밋으로 찾는다(자기 자신의 해시를 문서에 미리 쓰지 않음).

## 2026-11-09 — OpenWiki Codex 사용자 연동

- 목표: 코드 근거를 연결한 기술 위키를 향후 유지할 수 있도록 공식 도구를 검토하고 설치한다.
- 변경: OpenWiki 0.9.0과 전용 Node 22.22.0, 사용자 범위 Codex 스킬/MCP 설정을 설치했다. 기존 포트폴리오/이슈와 역할을 구분했다.
- 판단: 시스템 Node를 교체하지 않고 도구 전용 런타임을 연결한다. 위키 생성은 별도 작업으로 둔다. Ponytail은 구현 단순화 지침으로 목적이 달라 이번에는 설치하지 않았다.
- 검증: Node 배포본 해시, 설치기 성공·Codex `installed`, 기존 설정 보존 확인. 별도 서버 초기 연결 검증은 Python 호환 문제 뒤 재시도 실행 승인이 거절되어 미실행. 앱 코드는 바꾸지 않았다.
- 후속: Codex 재시작 후 도구 인식 확인, 필요 시 위키 초기화. 공개 자료에서는 로컬 도구 설치와 제품 기능/실행 검증을 구분한다.
- 근거: [설치 기록](../issues/2026-11-09-openwiki-install.md). 이 항목의 추가 커밋은 Git 이력으로 추적한다.

## 2026-11-09 — 불필요한 OpenWiki 제거

- 사용자 목표: 코드 단순화에 필요하지 않은 도구를 제거해 설치 용량을 정리한다.
- 변경: 공식 제거 명령으로 스킬/MCP 설정 해제 후 전용 Node·패키지·설치 ZIP·백업/스크립트·실행 진입점을 삭제했다. 공유 캐시와 앱 코드는 건드리지 않았다.
- 판단: 새 도구 도입은 실제 작업 목적과 유지 비용에 맞춰 결정한다. 포트폴리오 문서 관리는 기존 작업 규칙으로 유지한다.
- 검증: 제거 명령 성공, 설정 블록 외 내용 동일, 전용 폴더·스킬·실행 진입점 없음, 기본 Node 20.20.0 유지. 전용 폴더 제거 전 파일 합계 약 334MiB. 제품 코드 변경이 없어 앱 테스트는 재실행하지 않는다.
- 근거: [제거 결과](../issues/2026-11-09-openwiki-install.md). 이전 설치 항목은 과거 이력으로 유지한다.

## 2026-11-09 — 휴대폰 방향 비교 계산과 모의 검증

- 목표: 경로와 반대 방향으로 휴대폰을 향한 경우를 포함해 방향 상태를 계산하고, UI·실제 센서 연결 전에 재현 가능한 모의값으로 검사한다.
- 구현: 경로 형상에서 진행 선분 방위 계산, 최단 각도 차의 좌우 부호, 정방향·좌우·반대 분류와 불확실한 입력의 확인 불가 처리. 기존 공유 모델을 사용하고 외부 패키지나 UI는 추가하지 않았다.
- 선택: 사람의 몸 방향을 추측하지 않는다. 진북 기준이 아니거나 오차를 알 수 없는 센서 값을 확정적인 방향 지시로 쓰지 않는다.
- 검증: 전체 단위 88개(추가 38개) 통과. 최초 ±30도/오차 ±5도 기대값 오류를 바로잡고 경계 검증을 유지했다. UI 연결이 없어 브라우저 테스트는 수행하지 않는다. 빌드는 실행 결과를 이슈에 기록한다.
- 미확인/다음: 화살표·문구 연결, 실제 방위 센서 축/진북 변환·권한/흔들림·현장 정확도. GPS 보행 검증과 TMAP 보류 범위도 유지한다.
- 근거: [계산 코드](../../shared/facing.ts), [모의 검증](../../tests/facing.test.ts), [상세 이슈](../issues/2026-11-09-facing-comparison.md). 커밋은 Git 이력으로 추적한다.

## 2026-11-09 — 앱 테스트 화면에 방향 카드 연결

- 목표: 잠깐 나타났다 사라지는 문구 대신 현재 방향에 맞는 화살표·문구를 같은 카드에 유지한다.
- 구현: 기존 방향 계산에 모의 각도/오차 조작과 표시 상태를 연결했다. 유효 상태는 800ms 유지 후 전환하고 확인 불가는 즉시 화살표를 가린다. 실제 GPS와 섞지 않고 모의임을 표시했다.
- 선택/한계: 모의 입력은 변경 전까지 유지하는 테스트값이며 실제 센서의 시각·오차를 대신하지 않는다. 몸의 방향도 추측하지 않는다. 경로/세션 변경·종료 시 타이머를 정리한다.
- 검증: 단위 88개, 첫 브라우저 26개(방향 카드 7+추적 19) 통과. 선택 표시/도착 검증 보완 뒤 방향 카드 7개 재실행 및 최종 빌드 통과. 390px 최종 캡처 육안 확인·보관. 모바일 360/390/430px 확인.
- 자료: [화면/검증 근거](evidence.md), [카드 코드](../../src/navigation/FacingGuide.tsx), [상세 이슈](../issues/2026-11-09-facing-card.md). 이번 추가 커밋은 Git 이력으로 추적한다.
- 다음: 실제 방위 센서·권한/축/진북 보정과 휴대폰 검증. HTTPS 배포/현장 GPS·TMAP 보류 범위는 유지한다.
