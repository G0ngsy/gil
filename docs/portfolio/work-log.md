## 2026-11-09 — 포트폴리오 자료 기반 정리

- 사용자 문제: 구현 이슈가 여러 문서에 흩어져 있어 완성 후 프로젝트의 판단·기여·결과를 다시 복원하기 어렵다.
- 변경: 별도 자료 폴더에 개요·현황·문제 해결 사례·검증/화면 근거·누적 기록을 구성했다. 상세 이슈는 보존하고 링크했다.
- 설계 판단: 개발 로그와 최종 사례 재료를 분리한다. 완료/모의 검증/실기기 미확인/보류를 구분하고 현재 코드를 기준으로 과거 이슈를 해석한다.
- 확인: Markdown 6개 문서의 로컬 링크 117개와 참조 커밋 15개 존재 확인, `git diff --check` 통과. 제품 코드 변경이 없어 제품 테스트는 재실행하지 않았다.
- 미확인: 최신 원격 배포·실기기·사용자 조사·정량 성과·공개용 기여 범위는 새로 확인하지 않았다.
- 후속: 구현 작업마다 현황과 이 기록을 갱신하도록 루트 작업 규칙에 추가한다. 최종 결과의 커밋 ID는 Git 이력에서 이 문서 추가 커밋으로 찾는다(자기 자신의 해시를 문서에 미리 쓰지 않음).

## 2026-11-09 — OpenWiki Codex 사용자 연동

- 목표: 코드 근거를 연결한 기술 위키를 향후 유지할 수 있도록 공식 도구를 검토하고 설치한다.
- 변경: OpenWiki 0.9.0과 전용 Node 22.22.0, 사용자 범위 Codex 스킬/MCP 설정을 설치했다. 기존 포트폴리오/이슈와 역할을 구분했다.
- 판단: 시스템 Node를 교체하지 않고 도구 전용 런타임을 연결한다. 위키 생성은 별도 작업으로 둔다. Ponytail은 구현 단순화 지침으로 목적이 달라 이번에는 설치하지 않았다.
- 검증: Node 배포본 해시, 설치기 성공·Codex `installed`, 기존 설정 보존 확인. 별도 서버 초기 연결 검증은 Python 호환 문제 뒤 재시도 실행 승인이 거절되어 미실행. 앱 코드는 바꾸지 않았다.
- 후속: Codex 재시작 후 도구 인식 확인, 필요 시 위키 초기화. 공개 자료에서는 로컬 도구 설치와 제품 기능/실행 검증을 구분한다.
- 근거: [설치 기록](../issues/2026-11-09-openwiki-install.md). 이 항목의 추가 커밋은 Git 이력으로 추적한다.
