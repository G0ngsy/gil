# 실제 검색·도보 경로 설정

## 현재 구현 범위

- 기본 화면은 실제 장소 검색이다. `/` 또는 `/?mode=live`로 연다. 고정 예시는 `/?preview=1`에서만 확인한다.
- 실제 모드는 장소 검색, 사용자 버튼으로 현재 위치 확인, 출발지·목적지의 보행 경로 요청, 공급자 거리·시간·지도 경로 표시와 접고 펼치는 전체 도보 안내 목록까지 구현했다.
- 현재 좌표·조회한 현재 주소·경로는 메모리에서만 처리한다. 현재 위치 확인 후 주소 표시, 주변 장소 검색, 도보 경로 계산에 필요한 좌표를 서버와 TMAP에 전달한다. 최근 검색어·선택 목적지는 별도 기록 정책에 따라 브라우저에 저장한다.
- 실제 모드의 GPS 시작 버튼으로 이동 추적·남은 거리·안내 단계 자동 진행·이탈/복귀·도착 판정을 연결했다. 연결 검증은 모의 GPS이며 실외 검증은 남아 있다. 카메라 안내는 미연결이며 기존 시안 카메라와 도착 화면은 가상 데이터다.

## TMAP 선정 이유

국내 장소 검색과 보행자 경로를 함께 제공하므로 TMAP REST API와 지도 SDK v2를 사용한다. 지도도 같은 제공사 SDK로 표시한다. 실제 운영 전 서비스 이용 조건·호출량·요금·지도 키의 허용 도메인 설정을 확인해야 한다.

## 키 발급 후 로컬 설정

1. SK open API에서 애플리케이션을 등록하고 장소 검색·보행자 경로 및 웹 지도 서비스 사용을 신청한다. 유료 플랜은 필요성과 예산 확인 후 사용자가 직접 선택한다.
2. `.env.example`을 `.env.local`로 복사한다.
3. `TMAP_APP_KEY`에 서버용 REST 키를 입력한다. `VITE_`로 시작하는 이름으로 바꾸면 안 된다.
4. 현재 `VITE_TMAP_MAP_KEY`는 비워 둔다. 지도 전용 키·도메인/API별 제한 지원은 공식 공개 자료에서 확인하지 못했다. 서버 키를 복사하지 않는다. 동일한 값은 실행/빌드에서 거부하지만 서로 다른 값만으로 권한 제한이 보장되지는 않는다.
5. `npm ci` 후 `npm run dev`로 시작한다. 이미 실행 중이면 재시작한다. `http://localhost:5173` 등 터미널에 표시된 주소를 연다.
6. 실제 홈 → 장소 검색 → 목적지 선택 → **현재 위치 확인** → **도보 경로 찾기**를 수행한다.
7. 지도 SDK의 인증과 지도 타일·경로 표시까지 실제 키로 확인한다. 브라우저·운영체제 위치 권한도 모두 허용되어 있어야 한다.

키 값은 채팅·스크린샷·GitHub에 올리지 않는다. 환경 파일은 Git에서 제외한다. `npm run preview`는 빌드된 정적 화면 확인용이며 API를 실행하지 않는다. 실제 기능은 `npm run dev` 또는 Vercel 환경에서 확인한다.

## Vercel 배포 시

이 저장소는 루트의 `vercel.json`을 기준으로 Vite 화면과 `/api/navigation` 함수를 함께 빌드한다. 과거 배포 기록은 있으나 이번 로컬 키 설정은 배포 환경에 자동 반영되지 않는다. 최신 배포의 키와 동작은 별도 확인한다.

- 현재 프로젝트 환경변수는 `TMAP_APP_KEY`만 서버 비밀 값으로 등록한다. `VITE_TMAP_MAP_KEY`는 등록하지 않는다.
- 두 값은 독립적이다. REST 키가 있으면 검색과 경로 총계 요청은 가능하지만 지도 키가 없으면 지도 준비 안내를 표시한다.
- 지도 키는 빌드 시 반영되므로 바꾸면 새로 배포해야 한다.
- HTTPS 주소에서 휴대폰으로 검색·위치·경로·지도 표시를 검증한다. 다른 기기의 `http://192.168...` 같은 일반 HTTP에서는 위치 권한을 사용할 수 없다.
- 공개 서비스로 확대하기 전에 호출량 제한, 비용 모니터링, API 남용 대응을 제공사·호스팅 설정과 함께 준비한다. 현재는 소규모 검증용이다.

## 최소 API 인터페이스

| 요청 | 동작 |
|---|---|
| `GET /api/navigation?action=config` | REST 키 설정 여부만 반환. 키 값은 반환하지 않음 |
| `GET /api/navigation?action=search&q=검색어` | 전국 관련도순 장소 검색 |
| `POST /api/navigation?action=search` | `{q,center:{lat,lng}}` → 반경 10km 거리순 장소 검색 |
| `POST /api/navigation?action=address` | `{point:{lat,lng}}` → GPS 기준 주변 주소·동네 이름 |
| `POST /api/navigation?action=route` | `{start:{lat,lng},end:{lat,lng}}` → 거리(m), 시간(초), 분리된 경로 선분, 안내점 |

제공사 좌표는 `[경도, 위도]`에서 `{lat,lng}`로 정규화한다. HTTP 응답은 저장하지 않으며 API 오류 원문과 인증키를 사용자에게 전달하지 않는다. 검색 결과의 거리는 검색 기준 좌표에서의 직선 거리이며 도보 시간으로 추정하지 않는다. 현재 위치가 없으면 전국 검색임을 표시한다. 현재 주소는 GPS 기준 주변 주소이며 GPS 오차·확인 시각과 함께 표시한다.

## 실제 연결 확인 — 2026-11-10

- 사용자 키 설정 후 기존 서버 처리 코드에서 실제 장소 검색·보행 경로 API가 HTTP 200으로 응답했다.
- 서울도서관 검색 17건, 공공 좌표에서 서울도서관까지 358m·305초, 선분 7개·안내점 8개를 확인했다. 사용자 현재 위치를 사용하지 않았다.
- 과거 같은 AppKey로 로컬 Chrome에서 지도·경로선의 기술적 동작은 확인했지만 공개 사용의 안전성을 검증한 것은 아니다. 같은 날 지도 설정을 비웠다. 배포 환경·실외 보행 검증은 남아 있다.
- GPS 자동 이동 추적은 실제 검색 경로에 연결했다. 방위 센서 카드는 테스트 모드에만 있으며 실제 검색 경로에는 미연결이다.
- 상세 범위는 [실제 API 검증 기록](validation-2026-11-10-tmap-live.md)을 참고한다.

## 실제 지도 확인 — 2026-11-10

실제 공급자 SDK의 비동기 로딩 오류를 수정하고 지도·경로선 표시를 확인했다. 당시 같은 키로 동작했으나 이 사실을 키 공유 권장으로 해석하면 안 된다. 현재 `.env.local` 지도 키는 제거했고 서버 키만 유지한다. [원인/검증](issues/2026-11-10-tmap-map-loader.md).

## 실제 경로 GPS 이동 안내 — 2026-11-10

경로를 받은 뒤 **GPS 이동 안내 시작**을 누른다. 이동에 따라 남은 거리·현재 안내·마지막 반영 위치를 갱신한다. 이탈 시 자동 재탐색은 하지 않으며 도착을 두 표본으로 확인하면 GPS를 종료한다. 중지/화면 종료/탭 숨김 후 자동으로 재시작하지 않는다. [구현과 검증 범위](issues/2026-11-10-live-route-tracking.md).

Vercel 환경변수는 사용자가 직접 `TMAP_APP_KEY`만 Secret으로 설정한다. 지도 키는 분리·권한 제한 확인 전까지 비워 둔다. 이용할 환경(Production/Preview)에 설정하고 새로 배포해야 한다. 로컬 환경 파일과 Git 푸시는 Vercel 환경변수를 대신 설정하지 않는다. 이번 작업에서 배포 환경은 변경하지 않았다.

## 현재 키 정책 — 2026-11-10 정정

지도 기술 검증과 키 공개의 안전성은 별개다. 서버 키를 브라우저에 공유하라는 이전 안내를 철회했다. [조사 근거·현재 조치·공급자 문의 사항](issues/2026-11-10-tmap-key-separation.md)을 따른다. 지도는 준비 문구를 표시하고 검색/경로/GPS 상태 기능은 유지한다.

## 2026-11-13 현재 카메라 안내

실제 카메라는 방향 센서 없이 지도와 같은 경로/GPS 행동 카드를 사용한다. 이전 센서 제한 조사 기록은 당시 방식이며 현재 실제 카메라 정책이 아니다. 카메라 배경 위 고정 화살표/안내점 거리이며 시선/바닥 AR이 아니다. [사용/모의 실행 방법](camera-setup.md).
