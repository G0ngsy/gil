# 실제 검색·도보 경로 설정

## 현재 구현 범위

- 기본 화면은 기존 디자인 시안이다. 홈의 **실제 장소로 길찾기**를 누르거나 `/?mode=live`로 이동한다.
- 실제 모드는 장소 검색, 사용자 버튼으로 현재 위치 확인, 출발지·목적지의 보행 경로 요청, 공급자 거리·시간·지도 경로 표시와 접고 펼치는 전체 도보 안내 목록까지 구현했다.
- 계정·데이터베이스·위치 저장 없이 메모리에서만 처리한다. 위치를 확인하는 단계에는 브라우저 센서만 사용하고, **도보 경로 찾기**를 누를 때 출발·도착 좌표를 서버와 TMAP에 전달한다.
- 실제 모드의 카메라·이동 추적·회전 단계 자동 진행·도착 판정은 다음 개발 범위다. 기존 시안의 카메라와 도착 화면은 가상 데이터다.

## TMAP 선정 이유

국내 장소 검색과 보행자 경로를 함께 제공하므로 TMAP REST API와 지도 SDK v2를 사용한다. 지도도 같은 제공사 SDK로 표시한다. 실제 운영 전 서비스 이용 조건·호출량·요금·지도 키의 허용 도메인 설정을 확인해야 한다.

## 키 발급 후 로컬 설정

1. SK open API에서 애플리케이션을 등록하고 장소 검색·보행자 경로 및 웹 지도 서비스 사용을 신청한다. 유료 플랜은 필요성과 예산 확인 후 사용자가 직접 선택한다.
2. `.env.example`을 `.env.local`로 복사한다.
3. `TMAP_APP_KEY`에 서버용 REST 키를 입력한다. `VITE_`로 시작하는 이름으로 바꾸면 안 된다.
4. `VITE_TMAP_MAP_KEY`에는 브라우저에서 사용하도록 발급한 지도 SDK 키를 입력한다. 공개되는 값이므로 비공개 REST 키와 분리하는 것을 권장한다. 서비스 콘솔에서 지원하는 허용 도메인·호출 제한을 확인한다.
5. `npm ci` 후 `npm run dev`로 시작한다. 이미 실행 중이면 재시작한다. `http://localhost:5173` 등 터미널에 표시된 주소를 연다.
6. **실제 장소로 길찾기** → 장소 검색 → 목적지 선택 → **현재 위치 확인** → **도보 경로 찾기**를 수행한다.
7. 지도 SDK의 인증과 지도 타일·경로 표시까지 실제 키로 확인한다. 브라우저·운영체제 위치 권한도 모두 허용되어 있어야 한다.

키 값은 채팅·스크린샷·GitHub에 올리지 않는다. 환경 파일은 Git에서 제외한다. `npm run preview`는 빌드된 정적 화면 확인용이며 API를 실행하지 않는다. 실제 기능은 `npm run dev` 또는 Vercel 환경에서 확인한다.

## Vercel 배포 시

이 저장소는 루트의 `vercel.json`을 기준으로 Vite 화면과 `/api/navigation` 함수를 함께 빌드한다. 과거 배포 기록은 있으나 이번 로컬 키 설정은 배포 환경에 자동 반영되지 않는다. 최신 배포의 키와 동작은 별도 확인한다.

- 프로젝트 환경변수에 `TMAP_APP_KEY`를 서버 비밀 값으로, `VITE_TMAP_MAP_KEY`를 브라우저용 공개 값으로 설정한다.
- 두 값은 독립적이다. REST 키가 있으면 검색과 경로 총계 요청은 가능하지만 지도 키가 없으면 지도 준비 안내를 표시한다.
- 지도 키는 빌드 시 반영되므로 바꾸면 새로 배포해야 한다.
- HTTPS 주소에서 휴대폰으로 검색·위치·경로·지도 표시를 검증한다. 다른 기기의 `http://192.168...` 같은 일반 HTTP에서는 위치 권한을 사용할 수 없다.
- 공개 서비스로 확대하기 전에 호출량 제한, 비용 모니터링, API 남용 대응을 제공사·호스팅 설정과 함께 준비한다. 현재는 소규모 검증용이다.

## 최소 API 인터페이스

| 요청 | 동작 |
|---|---|
| `GET /api/navigation?action=config` | REST 키 설정 여부만 반환. 키 값은 반환하지 않음 |
| `GET /api/navigation?action=search&q=검색어` | 장소 ID·이름·주소·분류·위경도 목록 |
| `POST /api/navigation?action=route` | `{start:{lat,lng},end:{lat,lng}}` → 거리(m), 시간(초), 분리된 경로 선분, 안내점 |

제공사 좌표는 `[경도, 위도]`에서 `{lat,lng}`로 정규화한다. HTTP 응답은 저장하지 않으며 API 오류 원문과 인증키를 사용자에게 전달하지 않는다. 검색 결과의 거리는 직선 거리이며 도보 시간으로 추정하지 않는다.

## 검증 명령

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 검증은 Chrome이 설치된 환경을 사용하며 지도 SDK·장소·경로 응답 및 위치 정보를 모의한다. 실제 TMAP 키의 인증·서비스 승인·요금·지도 렌더링을 검증한 것으로 간주하지 않는다.

## 실제 연결 확인 — 2026-11-10

- 사용자 키 설정 후 기존 서버 처리 코드에서 실제 장소 검색·보행 경로 API가 HTTP 200으로 응답했다.
- 서울도서관 검색 17건, 공공 좌표에서 서울도서관까지 358m·305초, 선분 7개·안내점 8개를 확인했다. 사용자 현재 위치를 사용하지 않았다.
- 현재 AppKey를 지도 설정에도 사용해 로컬 Chrome에서 실제 지도·마커·경로선 표시를 확인했다. 지도 키는 브라우저에 공개되는 값이다. 배포 환경·실외 보행 검증은 남아 있다.
- 자동 이동 추적과 방향 안내는 테스트 모드 구현이며 실제 검색 경로와의 연결은 다음 작업이다.
- 상세 범위는 [실제 API 검증 기록](validation-2026-11-10-tmap-live.md)을 참고한다.

## 실제 지도 확인 — 2026-11-10

실제 공급자 SDK의 비동기 로딩 오류를 수정하고 지도·경로선 표시를 확인했다. 별도 키 발급이 필수인 것은 아니며 현재 키로 동작했다. `.env.local`의 지도 설정만 로컬에 반영했고 키는 커밋하지 않았다. [원인/검증](issues/2026-11-10-tmap-map-loader.md).
