# 실제 경로 확인·이동 안내 화면 단순화

## 문제
실제 경로 UI에 검증용 GPS 상태·반복 설명·시작/중지 버튼·전체 경로 확인 기능이 동시에 쌓였다. 지도 키가 없는 배포에서는 큰 빈 지도 영역까지 보여 초기 디자인의 간결한 안내 화면과 달라졌다. 휴대폰에서 주요 동작을 보려면 여러 번 스크롤해야 했다.

## 원인
경로 확인과 이동 안내를 한 시트에 함께 표시했고, 추적 시작 이후에도 비활성 시작 버튼과 중지 버튼을 동시에 렌더링했다. 지도 미설정/오류에도 지도 표시용 최소 높이를 유지했다.

## 해결방법
RouteJourney를 분리해 시작 전 목적지·전체 예상 시간/거리·길 안내 시작을 중심으로 표시한다. 시작 시 안내 단계로 전환하며 시작 버튼을 제거한다. 다음 이동 문구는 실제 route.steps의 현재 단계에서 가져오고, GPS 대기/반영 거부/이탈/도착을 우선 표시한다. 남은 시간은 계산하지 않고 남은 거리만 표시한다. 일시중지/종료는 상단 안내 메뉴에 두고, 중지 상태에서만 안내 계속하기를 보여준다. 종료 확인창과 GPS 해제 수명주기는 유지한다. 뒤로 가기는 추적을 중지하고 경로 확인으로 돌아간다.

전체 도보 안내·전체 예상 시간·GPS 상태·안내 단계·부가 설명은 닫힌 자세히 보기에 묶는다. 지도 키 없음/오류는 compact 안내로 줄이고 동작하지 않는 지도 위치 버튼을 숨긴다. 오류 재시도는 유지한다. 지도 사용 가능 시 실제 타일 공간은 유지한다. 안내 화면의 서버 연결 상태 footer는 숨겨 핵심 안내에 집중한다.

## 결과
빌드·단위 109개 통과. 기존 전체 브라우저 91개 통과와 새 모바일 UI 3개 별도 통과. GPS 진행/이탈/복귀/도착과 중지·재시작·늦은 콜백 거부를 새 조작 흐름으로 검증했다. 지도 오류 높이 축소·시작 버튼의 화면 내 표시·주 안내/남은 거리·접힌 상세·키보드 메뉴를 360/390/430px에서 확인했다. 실제 지도 키 문제나 실제 경로의 카메라/방위 연동을 해결한 작업은 아니다.
