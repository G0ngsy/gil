# 경로·휴대폰 방향 비교와 모의값 검증 (2026-11-09)

## 문제
GPS 진행 계산만으로는 정지한 휴대폰이 경로의 정방향인지 반대 방향인지 판정할 수 없었다. 실제 센서 연결 전에 좌우 부호와 0/360도 경계, 불확실한 입력을 검증할 필요가 있었다.

## 원인
현재 위치·경로 진행과 휴대폰 방위는 별개의 입력이다. GPS 이동 방향이나 원시 기기 회전값을 진북 기준 휴대폰 방위로 간주할 수 없다. 휴대폰이 향한 방향과 사용자의 몸이 향한 방향도 항상 같지 않다.

## 해결방법
- `shared/facing.ts`에 UI/센서와 분리된 순수 함수를 추가했다. `routeBearingAt`은 경로 형상의 진행 거리로 현재 선분 방위를 계산한다. 경로가 꺾이는 정확한 지점은 나가는 선분을 선택하고, 중복 좌표와 단절된 선분 사이에 가상 연결선을 만들지 않는다. 경로 끝·빈 경로·훼손 좌표·1m 미만 선분은 방위를 확정하지 않는다.
- `compareFacing`은 진북 기준 시계방향 휴대폰 각도와 경로 방위의 최단 각도 차(-180~180도)를 비교한다. 양수는 경로가 휴대폰의 오른쪽, 음수는 왼쪽에 있다는 뜻이다. 좌우는 경로의 회전 지시가 아니라 휴대폰 방향 보정 상태다.
- 차이 절댓값 25도 이하 `forward`, 155도 이상 `opposite`, 나머지는 `left`/`right`로 분류한다. 오차 구간의 양 끝이 다른 상태에 걸치면 `unknown`으로 처리한다.
- 방위가 없거나 진북 기준이 아닌 값, 각도 범위/시각 오류, 3초 초과 오래된 방위, 20도 초과 또는 알 수 없는 오차는 확인 불가다. 위치 없음·거부된 GPS·10초 초과 오래된 위치·경로 이탈·도착 상태에서도 방향을 단정하지 않는다.
- 모의 진북 방위를 주입해 네 방향과 확인 불가 상태의 전환을 테스트했다. 화면·센서 권한·DeviceOrientation·카메라/AR 연결과 UI 문구는 추가하지 않았다.

## 결과
- 단위: 전체 88개 통과(새 방향 비교 38개 + 기존 50개). 동서남북, 0/360도 경계, 꺾임, 단절, 불확실한 분류 경계, 오래된/잘못된 입력, 위치 불가·이탈·도착, 상태 전환을 검증했다.
- 초기 검증 실패: ±30도에 ±5도 오차를 준 테스트는 정방향 경계 25도에 걸쳐 확인 불가가 맞는데 좌우로 기대했다. 명확한 좌우 샘플을 ±40도로 바꾸고 경계 전용 테스트를 유지한 뒤 재실행했다.
- 빌드: TypeScript 검사 및 Vite 프로덕션 빌드 통과.
- 미확인: 실제 방위 센서, 진북/자북 보정, 화면 회전/기기 자세에 따른 축 변환, 센서 권한·흔들림, 실제 휴대폰·실외 방향 정확도, 사람 몸의 방향은 검증하지 않았다. UI와 실제 GPS 흐름은 이번 함수에 연결하지 않았다.
- 제한: 각도/시간 임계값은 모의 테스트 기준이며 현장 검증된 기준이 아니다. 경로 매칭이 잘못되면 방위도 잘못될 수 있다. 완전 중첩 경로의 진행 방향 모호성은 기존 제한으로 남아 있다. 정지 상태의 실제 방향 안내가 완성됐다는 의미가 아니다.
