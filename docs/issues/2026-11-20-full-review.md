# 누적 기능 전체 점검 (2026-11-20)

## 문제
사용자 요청으로 최신 구현을 전체 점검했다. 2026-11-18 중단 전의 전체 검사 완료 결과는 남아 있지 않아 재실행하며, 원격의542ff84 방향 안내 계획 문서를 먼저 반영했다. 해당 커밋은 계획 문서이며 제품 방향 기능을 추가한 것이 아니다.

재현한 제품 문제는 두 가지다.
1. 단발 위치의 정확도를 개선하는 임시 watchPosition이 화면 이동 때 즉시 해제되지 않았다.
2. 서버/API/UI에서 허용하는 회전 단계 빈 목록이 저장 데이터 검사에서는 거부돼, 해당 경로가 안내 복원 후보에 저장되지 않았다.

## 원인
- locate는 요청 버전만 바꿔 늦은 결과를 무시했고 getUserPosition의 취소 신호를 연결하지 않았다. 임시 감시는 최대 대기 시간까지 남을 수 있었다. 화면 이동 시 주소 요청도 중지 대상에서 빠져 있었다.
- API 경로 검증은 steps:[]를 허용하지만 parseSavedGuidance는 적어도 한 단계가 있어야 한다고 판단했다. 이동 가능한 경로 선분과 회전 설명의 유무가 다른 조건인데 함께 묶였다.
- 오래된 주변 위치 갱신을 취소하면 locate가 null을 반환한 뒤 취소된 검색이 ‘위치 갱신 실패’ 메시지를 쓰는 경로도 코드 대조로 확인했다.

## 해결방법
- 단발 위치 요청별 AbortController를 연결한다. 새 위치 확인·뒤로가기·개인정보 안내 이동·컴포넌트 해제 때 임시 감시를 해제하고 주소 요청도 취소한다. 진행 중인 실제 안내 GPS 세션은 별도 훅이므로 화면 이동만으로 종료하지 않는다.
- 위치 갱신을 기다린 검색은 취소 상태를 먼저 확인하고, 취소된 요청의 오류를 새 화면에 표시하지 않는다.
- 회전 단계 빈 배열을 복원 형식에서도 허용한다. 유효하지 않은 좌표/단계/경로 검사와 크기·기간 제한은 유지한다. 없는 회전 안내를 만들지 않는다.
- 두 재현 사례와 취소된 검색의 늦은 결과를 회귀 검사로 추가했다. 빈 회전 목록의 저장 파서 단위 검사도 추가했다.
