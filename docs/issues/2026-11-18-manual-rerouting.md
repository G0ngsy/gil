# 경로 이탈 후 수동 재탐색 (2026-11-18)

## 문제
기존 안내는 경로 이탈을 표시하지만 현재 위치에서 기존 목적지로 다시 경로를 찾는 동작이 없었다. 실외 재확인이 어려워 모의 GPS로 구현·검증 가능한 작업을 우선했다.

## 원인
검색 시 최초 경로 생성과 진행 중 안내 세션이 분리돼 있었다. 단순히 최초 경로 함수를 재사용하면 검색 중인 장소나 출발점 상태를 바꾸거나 기존 안내를 먼저 삭제할 수 있다. 최초 검증에서 X 홈 이동이 일반 뒤로가기와 달리 취소 경로를 거치지 않아 늦은 응답이 적용되는 문제도 발견했다.

## 해결방법
- 이탈 시 ‘현재 위치에서 다시 찾기’ 표시. 자동 반복 호출은 하지 않는다.
- 안내 세션의 목적지/입구/POI ID를 유지하고 최근10초 이내·오차30m 이하 관측을 출발점으로 사용한다. 없으면 새 위치를 요청하며 정확하지 않으면 경로 요청을 보류한다.
- 새 경로를 받을 때만 세션 경로/출발점/진행을 교체한다. 실패하면 기존 안내와 거리를 유지하고 재시도한다. 요청 중에도 기존 GPS 진행은 계속된다.
- 중복 클릭 차단,30초 응답 제한, 홈/X/뒤로가기/탭 숨김/페이지 이탈/안내 종료/새 안내/도착/수신 중단/컴포넌트 해제 시 요청 취소와 늦은 응답 무효화.
- 위치 재확인에도 취소 신호를 연결해 임시 위치 감시를 해제한다. 브라우저 단발 위치 요청 자체는 취소 API가 없어 늦은 결과를 무시한다.
- 경로 요청은 위경도와 필요한 POI ID만 보내도록 정리했다. 정확도·수신 시각·장소 이름 등은 경로 요청 본문에 보내지 않는다.
- 검증 중 기대 본문과 실제 본문의 불필요한 위치 메타데이터 차이를 발견해 위 정리를 반영했다. 지도 오류와 재탐색 오류를 동시에 가진 테스트는 재탐색 영역 안의 오류를 확인하도록 범위를 수정했다.

## 결과
검증 결과와 배포 상태는 최종 확인 후 아래에 기록한다. 모의 GPS/API 검증은 실외 정확도나 실제 공급자 재탐색 품질 검증이 아니다. 기존 시안·센서 시뮬레이션은 변경하지 않았다. AI 지원 구현·검증·문서화.

최종 로컬 검증: 빌드·단위124개·브라우저53개 통과(재탐색10개 포함). 360/390/430px, 성공·실패/재시도·중복 차단·위치 재확인·부정확 차단·홈/X/페이지 이탈·시간 초과·종료 후 늦은 응답을 모의 GPS/API로 검증했다. 초기 재탐색8개 중6개 실패는 X 취소 누락/요청 본문 메타데이터/오류 선택 범위 문제를 수정하고8개 재통과, 경계2개 추가 후 최종53개 통과. 실제 TMAP 재탐색 및 갤럭시 실외 품질은 미검증. 커밋/배포 확인은 별도 기록.
