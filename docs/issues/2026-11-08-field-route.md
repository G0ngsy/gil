# 현장 테스트 경로 설정 (2026-11-08)

## 문제
서울시청 인근의 고정 경로만 사용해 다른 장소의 실외 GPS 추적·이탈·도착을 검증할 수 없었다.

## 원인
경로와 안내 단계, 초기 거리, 모의 좌표 버튼이 특정 예시 좌표에 묶여 있었다.

## 해결방법
- `/?mode=simulation`의 ‘현장 테스트 경로 설정’에서 출발·경유·도착 좌표를 순서대로 입력할 수 있게 했다. 한 줄에 `위도, 경도` 형식을 사용한다.
- 지점 2~20개, 인접 간격 5~500m, 전체 길이 40m~2km로 제한한다. 잘못된 좌표·빈 필드·중복/근접 지점·극지/날짜변경선 구간 등을 거절한다.
- 입력 검증이 끝난 뒤에만 기존 GPS를 해제하고 경로·진행·거리·단계·지도 범위·모의 입력 출발 좌표를 초기화한다. 검증 실패는 진행 중인 추적과 기존 경로를 보존한다. 경로 적용으로 생길 동작은 입력 화면에 미리 표시한다.
- 새 경로를 지도 도식, 실제 GPS, 모의 수동 좌표 입력에 연결했다. 서울시청 전용 좌표 버튼은 현장 경로에서 숨기고 예시 복원 시 다시 표시한다.
- 남은 거리는 입력 지점을 이은 선분 길이를 사용한다. 실제 보행 거리·ETA·회전 안내로 표현하지 않으며 출발/경유/도착 테스트 지점만 안내한다.
- 현장 경로는 메모리에서만 사용한다. 저장·외부 전송하지 않고 새로고침하면 기본 예시로 돌아간다. 서울시청 예시 복원 버튼도 제공한다.

## 결과
- 검증: 단위 테스트 50개 통과. 좌표 파싱·거리·단계·도착과 잘못된 입력 15종을 포함한다. TypeScript 검사·프로덕션 빌드 통과.
- 브라우저·화면: 추적 브라우저 테스트 19개 통과. 현장 경로 적용·늦은 GPS 무시·새 경로 GPS 수신·잘못된 입력 시 추적 보존·예시 복원·새로고침 초기화·외부 API 호출 없음과 360/430px 가로 넘침 없음을 확인했다. 360px 도식 캡처를 열어 경로와 거리·단계 표시를 확인했다.
- 미확인: 실제 기기·실외 GPS, 현장 좌표의 도로/통행 가능 여부, GPS 판정 임계값 현장 보정. HTTPS 테스트 주소 배포와 TMAP 키·실제 경로·재탐색 연동은 수행하지 않았다.
- 제한: 직접 설정한 직선 경로는 도로망을 따르지 않는다. 실제 보행 구간을 따라 충분한 경유점을 입력해야 한다. 큰 모의 좌표 점프는 기존 추적 검증에서 거부될 수 있다.

## 확인 방법
HTTPS 또는 localhost에서 `/?mode=simulation` → 현장 테스트 경로 설정 → 출발/경유/도착 좌표 입력 → 현장 경로 적용 → 실제 GPS 추적 시작을 선택한다. 모의 테스트는 경로 적용 후 자동으로 채워진 출발 좌표를 보내고, 다음 좌표를 수동 입력해 진행한다. 도착은 근접·정확도 조건을 만족하는 좌표 두 번으로 확정한다. 실제 휴대폰 외부 접속용 HTTPS 주소는 별도 준비가 필요하다.
