# 목적지 핀/경로 끝 불일치와 현재 위치 사용자 보고

## 문제
사용자가 경기도서관점 경로 사진3장과 함께 경로가 너무 간결하고 현재 위치가 잘못 잡힌다고 보고했다. 후속 질문에서 건물 밖에서도 위치가 틀렸다고 확인했다. 사진에는 장소 핀이 경로선 끝과 떨어져 있고 지도/카메라 모두 이탈 상태였다. 당시 실제 좌표·GPS 오차·오프셋 크기·기기 진단은 없어 사진만으로 GPS 원인을 확정할 수 없다. 사용자 사진 원본은 저장소에 복사하지 않았다.

## 원인 확인
앱은 TMAP LineString의 점을 모두 사용하며 splitRoute도 실제 선분을 보존한다. 경로를 단순화해 점을 버리는 코드는 없었다. 건물 내부 통행선이 공급자 응답에 없다고 임의로 선을 만들어서는 안 된다.

검색은 장소 중심점을 유지하지만 기존 경로 요청은 공급자 입구점/POI ID를 전달하지 않았다. 목적지 표시도 장소 중심점 하나뿐이라 TMAP 보행 경로 끝과 같다고 오해할 수 있었다. 공개 장소명으로 실제 검색하고, 장소에서 남/서0.0005도 떨어진 **임의 출발점**으로 요청하니409m/3선분/15점/4안내점, 경로 끝→장소32m 차이가 재현됐다. 사용자109m 경로 자체를 재현한 것은 아니다. 해당 POI는 입구점과 중심점이 같았고, 입구/POI ID를 전달한 뒤에도32m 차이가 남았다. 공급자 데이터 범위를 앱 코드만으로 메울 수 없다.

현재 위치는 1회 수신 오차100m 이하를 바로 채택하고 경로 생성 때 최대2분 전 좌표도 사용했다. 개선 여지가 있으나 이것이 사용자 실외 위치 오류의 확정 원인은 아니다.

## 해결방법
- 중심점과 입구점을 구분해 보존하고, 유효한 입구 좌표/숫자 POI ID를 경로 요청에 전달한다. 잘못된 ID는 공급자 호출 전 거절한다.
- 실제 경로 끝을 경로 도착점으로 표시한다. 장소와15m 넘게 떨어지면 장소 위치도 별도 표시하고 차이/현장 출입구 확인을 안내한다. 새 직선·거리·건물 출입구를 만들지 않는다. 도착 판정 기준은 여전히 제공 경로 끝이다.
- 전체 경로 상세 보기로 제공자의 출발~도착 원문 안내를 단계별 표시한다. 현재 행동 카드와 구분한다.
- 최초 위치 오차30~100m이면 최대8초 동안 추가 고정밀 수신을 기다려 더 나은 좌표를 선택한다. 여전히30m 초과면 홈/주변 검색의 대략 위치로는 쓸 수 있으나 경로 생성은 보류한다. 100m 초과/잘못된 시각은 기존처럼 거부한다.
- 경로 생성 전에10초 초과 위치나30m 초과 오차를 다시 확인한다. 추가 수신 watch/timer는 성공/오류/화면 숨김/페이지 이탈 때 해제한다. 기존 GPS 시작·지도 범위·센서 정책을 유지하고 지도에 보고된 GPS 오차를 표시한다.

## 검증
단위124개, 관련 브라우저38개 통과. 최종 위치 정리 보완 후 개선/보류2개를 재실행한다. 최종 빌드는 후속 결과를 따른다. 신규 범위는 입구좌표/ID 전달·잘못된 ID 거부·경로 점 보존·도착점/장소 분리·상세목록·70m→8m 위치 개선·70m 유지시 경로 차단이다.

실제 TMAP 지도 SDK + 실제 공공 장소의 검색/409m 경로 응답을 로컬에 주입하고 출발 GPS만 모의로 설정해 경로 도착점/장소 분리 및4단계 상세 표시를 확인했다. 페이지 예외0개. [지도](../portfolio/assets/2026-11-13-route-endpoint-gap-390.png), [상세](../portfolio/assets/2026-11-13-route-details-390.png). 공급자 원본 응답은 검증용 임시 파일로만 사용하고 제거한다. 키/인증 URL/실제 사용자 GPS는 기록하지 않았다.

## 미확인/다음
실외 GPS의 실제 오프셋·휴대폰 보고 정확도 자체는 확인하지 못했다. 낮은 오차로 잘못된 좌표를 보고하는 기기는 이 보완으로 교정된다고 보장할 수 없다. 해당 장소 공급자 경로 끝과 건물 위치 차이는32m 남아 있고 건물 내부 통행을 제공하지 않는다. 출입구/통행 경로는 현장에서 확인해야 한다. 배포와 푸시·모의 검증/실외 확인을 구분한다.

공식 근거: [POI 응답](https://tmap-skopenapi.readme.io/reference/poi-%EA%B2%80%EC%83%89-%EC%83%98%ED%94%8C%EC%98%88%EC%A0%9C), [보행자 endPoiId](https://tmap-skopenapi.readme.io/reference/%EB%B3%B4%ED%96%89%EC%9E%90-%EA%B2%BD%EB%A1%9C%EC%95%88%EB%82%B4). 기준b42e3de 이후 작업. AI 지원 조사·수정·검증·문서화.

추가 보완: 장소와 떨어진 경로 끝에 도달하면 지도/카메라에서 경로 도착점 도착으로 표시하고 실제 출입구 확인을 안내한다. 일반 목적지 도착과 구분하며 이 경우 홈 상태도 안내 완료로 표현한다. 개인정보를 저장하거나 실제 사용자 좌표를 재전송하지 않았다.

최종 회귀에서 일반 도착까지 홈 제목을 안내 완료로 바꾼 영향으로 기존1개가 실패했다. 경로/장소 차이가 있는 경우에만 새 문구를 적용하고 일반 도착은 보존하도록 조건을 수정했다. 해당 세션 검증을 재실행한다.

최종 결과: 단위124개·최종 빌드 통과. 초기 관련38개 통과 후 지도/카메라/세션22개 중21개 통과, 일반 도착 문구1개 회귀를 수정해 최종 세션9개 재통과. 위치 정리 후 개선/보류2개도 재통과했다. 범위가 중복되며 전체 브라우저 모음을 마지막 변경 후 일괄 실행한 것은 아니다. 링크306개·변경 형식 검사 통과. React 검토에서 지도/카메라의 같은 도착 상태·원본 선분 보존·위치 수신 정리·오차/시간 검사·상태 접근성을 확인했다.
