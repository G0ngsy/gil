# TMAP 서버 키의 지도 공유 안내 정정

## 문제
이전 안내와 로컬 검증에서 같은 AppKey를 TMAP_APP_KEY와 VITE_TMAP_MAP_KEY에 넣었다. 기술적 작동 확인을 공개 배포의 안전성 확인으로 잘못 확대했고 사용자가 키 노출 문제를 지적했다.

## 원인
지도 SDK는 브라우저에서 키를 사용한다. VITE_ 변수는 빌드 결과에 포함되므로 호스팅의 Secret 저장 설정으로 감출 수 없다. 별도 키 발급·도메인 제한·API 권한 제한 지원 여부를 확인하지 않고 같은 키 설정을 권했다.

## 공식 자료 확인 — 2026-11-10

- [Vite 환경변수](https://vite.dev/guide/env-and-mode): VITE_ 값이 클라이언트에 포함됨을 명시한다.
- [TMAP 개발 가이드](https://tmapapi.tmapmobility.com/main.html): JS V2 지도 SDK 및 SK open API 앱/API 사용 안내로 연결된다.
- [SK 앱 사용 안내](https://openapi.sk.com/products/detail?menuSeq=126&svcSeq=60), [API 사용 안내](https://openapi.sk.com/products/detail?menuSeq=122&svcSeq=60): 이번 공개 페이지 조회에서는 지도 전용 키·API별 권한·도메인/Referer 제한을 설명하는 본문을 확보하지 못했다. 관련 공식 검색에서도 확인하지 못했다. 기능이 없다는 증거는 아니다. 로그인한 계정 설정은 이번에 직접 확인하지 않았다.
- [TMAP 약관](https://tmapapi.tmapmobility.com/terms.html): 동일 서비스를 위한 다수 프로젝트 생성 사용에 관한 제한이 있다. 키 분리 목적으로 새 앱을 임의 생성하도록 안내하지 않는다. 공급자에게 허용 방법을 확인한다.

## 해결방법

- 로컬 VITE_TMAP_MAP_KEY를 비우고 서버 키는 유지했다. 공급자 콘솔/키 재발급과 Vercel 환경은 변경하지 않았다.
- 설정 예제와 현재 안내를 정정했다. 지도 키는 보류한다. 키가 없으면 기존 지도 준비 문구를 표시하며 검색·경로·GPS 상태 기능은 유지한다.
- Vite 설정에서 서버/지도 키가 동일하면 값 출력 없이 실행·빌드를 거부한다. 다른 값은 권한 제한의 증거가 아니며 이 검사는 같은 키 재사용 실수만 방지한다. 비밀 키를 숨기기 위한 지도 프록시나 새 지도 공급자는 도입하지 않았다.
- 과거 지도 화면은 기술 검증 자료로 보존한다. 현재 지도 공개 배포 안전성이나 활성 설정 근거로 쓰지 않는다.

## 결과

설정 검사 3개: 동일 값 거부, 지도 값 공백 허용, 다른 값 허용. 정상 빌드 통과, 로컬 서버 키 존재/지도 키 공백 확인, dist 전체에서 실제 서버 키의 원문/URL 인코딩 일치 0건 확인. 키 값은 기록하지 않았다. 현재 빌드 검사이며 과거 빌드/배포/로그/브라우저의 노출 부재를 보장하지 않는다. 제품 UI 변경이 없어 브라우저/전체 단위 테스트는 재실행하지 않았다.

## 남은 확인과 다음 실행

공급자 SUPPORT에 다음을 확인해야 한다(문의는 자동 발송하지 않았다).

1. 하나의 길빛 서비스에서 서버 REST와 브라우저 JS V2 인증을 분리하는 공식 방법은 무엇인가?
2. 지도만 허용하는 키, 허용 도메인/Referer·IP 제한, API별 차단 또는 사용량 제한을 지원하는가? 각 제한이 어떤 호출에 적용되는가?
3. 서버/지도 키 분리를 위한 추가 앱/키가 약관상 허용되는가? 공개된 지도 키로 POI/보행 경로 호출을 차단할 수 있는가?

답변 전에는 지도 키를 비워 둔다. 사용자가 등록한 Vercel 서버 키는 Secret으로 유지한다. 이전 같은 키가 외부 배포/공유됐는지는 미확인이다. 공개됐다면 공급자의 키 폐기/교체 절차를 진행하고 서버 설정을 갱신해야 한다. 에이전트가 로컬 확인에서 키를 사용한 사실만으로 인터넷 공개 배포를 단정하지 않는다.
