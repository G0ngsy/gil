# 실제 테스트 진입에서 예시 데이터 분리

## 문제
실제 경로 기능을 확인할 단계인데 기본 주소가 고정 예시 목적지·가상 지도·거리 화면을 열었다. 실제 검색 화면에도 예시 화면 복귀 버튼이 있어 사용자가 실데이터 검증 여부를 혼동할 수 있었다.

## 원인
초기 디자인 시안을 기본 진입으로 유지했고 모의 센서 페이지는 mode=simulation만으로 접근할 수 있었다. 예시 UI와 실제 기능의 소스 진입도 한 파일에 묶여 있었다.

## 해결방법
기본 진입을 LiveNavigation으로 전환한다. preview=1이 없는 모든 예전 screen/mode 주소도 실제 검색으로 연다. 실제 화면에서 시안 복귀 버튼과 키 미설정 시 예시로 유도하는 문구를 제거한다. 고정 예시 UI는 DemoApp, 모의 GPS는 SimulationNavigation의 별도 모듈로 분리하고 명시적인 검토 모드에서만 불러온다. 자동 테스트 fixture는 보존하고 테스트 주소를 검토 모드로 명시한다. 기존 예시 저장 기록은 실제 기록으로 이관하지 않으며 사용자 저장값을 임의 삭제하지 않는다.

## 검증 중 발견한 문제
React.lazy/Suspense로 검토 화면을 나중에 표시하자 브라우저 시계를 정지하는 테스트에서 모의 화면 렌더링 대기가 끝나지 않았다. 화면 진입 전에 해당 검토 모듈을 동적으로 불러온 후 루트를 렌더링하도록 수정했다. 실제 화면에는 검토 코드가 로드되지 않는 조건을 유지한다. 처음 실패한 실행은 중단하고 수정 후 전체 검증을 다시 실행한다.

## 결과
빌드·단위 102개·전체 브라우저 83개 통과, 실제 배포 기본 진입과 실제 TMAP 검색/경로 HTTP200 확인. 빌드·단위·브라우저·배포 결과는 docs/validation-2026-11-11-live-default.md에 기록한다. 이 분리는 테스트 정확도 향상을 위한 진입 정책이며 실외 길 안내·AR 완료를 의미하지 않는다. preview=1은 접근권한 제어가 아닌 명시적인 검토 화면 선택이다.
