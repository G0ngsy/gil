# 실제 TMAP 지도 SDK 비동기 로딩 오류

## 문제
2026-11-10 실제 키로 SDK HTTP 200을 받아도 `sdk.LatLng is not a constructor`가 나와 지도가 표시되지 않았다. 기존 브라우저 테스트는 준비된 SDK를 주입해 이 문제를 발견하지 못했다.

## 원인
실제 부트스트랩은 document.write로 본체를 넣는다. 동적으로 추가한 비동기 script에서는 본체가 로드되지 않아 Tmapv2 이름만 있고 생성자가 없었다. 단순 준비 시간 지연이라는 초기 추정과 달랐다.

## 해결방법
공급자 부트스트랩의 singleFile 옵션으로 document.write를 건너뛰고, 반환한 공식 자산 경로를 허용 목록으로 확인한 다음 본체를 순서대로 로드한다. 필수 생성자를 모두 확인한 후에만 준비 완료로 처리하며 실패 시 상태를 정리해 재시도한다. 공급자 로더 구조 변경 시 재검증이 필요하다.

## 결과
실제 Chrome 390×844에서 SDK 200, 지도 타일 성공 응답 73건, 이미지 32개, 페이지 예외 0개, 지도·출발/도착 마커·청록 경로선을 화면에서 확인했다. 실제 API 거리 358m·305초·안내점 8개. 위치만 서울 시청 인근 공공 좌표로 주입했다. 사용자 현위치/휴대폰/배포 검증은 아니다. [화면](../portfolio/assets/2026-11-10-tmap-live-map-390.png).

회귀 검증은 별도 테스트의 부트스트랩/본체 순차 로딩·동시 요청 중복 방지·실패 정리/재시도와 기존 길찾기 흐름을 확인한다. AI 지원으로 진단·수정·자동 검증·문서를 작성했다.

최종 자동 검증: 단위 100개, 관련 브라우저 18개(로더 2개+기존 16개), 빌드 통과. 첫 빌드의 테스트 모듈 경로 해석 오류는 변수 경로로 수정 후 재빌드했다.
