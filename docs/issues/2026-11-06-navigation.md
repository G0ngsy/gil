# 실제 장소 검색·도보 경로 구현 중 문제 기록

작성일: 2026-11-06

## 1. 시안 정보가 실제 경로로 오인될 수 있음

- **문제:** 기존 화면의 520m·8분·30m 앞 우회전은 목적지가 바뀌어도 고정된 값이었다.
- **원인:** 디자인 검토용 가상 데이터와 화면 전환만 구현되어 있었다.
- **해결방법:** 실제 검색 모드를 별도 데이터 흐름으로 분리했다. 제공사 응답의 총 거리·초·선분만 표시하고 검색 결과의 직선 거리에는 '직선'을 표시했다. 실제 모드에는 가상 회전·도착·카메라 안내를 노출하지 않는다.
- **결과:** 모의 API 브라우저 테스트에서 340m·301초 응답이 340m·6분으로 표시되고 고정 회전·카메라 버튼이 없는 것을 확인했다. 기존 시안은 유지했다.

## 2. 실제 TMAP 키가 없음

- **문제:** 개발자 계정과 발급 키가 없어 실제 서비스 인증과 경로 응답을 확인할 수 없다.
- **원인:** 아직 API 서비스 등록 전 단계다.
- **해결방법:** 키 설정 여부 확인, 준비 안내, `.env.example`, 발급 후 설정 문서를 추가했다. 비공개 REST 키는 서버에서만 사용하고 브라우저 지도 키는 별도 설정한다.
- **결과:** 키가 없는 실제 개발 서버에서 검색 버튼이 비활성화되고 시안 복귀가 가능한 것을 확인했다. **실제 인증·서비스 승인·지도 SDK 렌더링·실외 경로 품질은 키 발급 후 확인이 남아 있다.**

## 3. 브라우저에 REST 키가 노출될 위험

- **문제:** 프론트엔드에서 TMAP REST API를 바로 호출하면 인증키가 화면 코드에 포함된다.
- **원인:** Vite의 `VITE_` 환경변수는 브라우저 번들에 공개된다.
- **해결방법:** `/api/navigation`에서만 `TMAP_APP_KEY`를 읽어 고정된 제공사 엔드포인트에 전달한다. 환경 파일을 Git에서 제외하고 응답은 `no-store`로 반환한다. 제공사 오류 본문을 전달하지 않는다.
- **결과:** 서버 테스트에서 인증키가 외부 요청 헤더에만 들어가고 프론트엔드 응답과 오류에 포함되지 않는 것을 확인했다. 브라우저용 지도 키는 별도 공개 설정이며 비밀로 취급하지 않는다.

## 4. 좌표 순서·누락된 경로 데이터로 잘못된 길을 그릴 위험

- **문제:** GeoJSON의 `[경도, 위도]`를 뒤집거나 빈 좌표를 숫자 0으로 처리하면 엉뚱한 위치를 표시할 수 있다.
- **원인:** 제공사·지도 SDK의 입력 형식 차이와 `Number('')`의 변환 특성이다.
- **해결방법:** 좌표와 총 거리·시간을 검사하고 `{lat,lng}`로 통일했다. 라인 사이를 임의로 연결하지 않고 각각의 선분으로 보존한다. 훼손된 응답에는 오류를 표시하며 직선 경로로 대신하지 않는다.
- **결과:** 빈 좌표·중복 장소·뒤바뀐 순서·총계 누락·분리 선분 테스트를 통과했다.

## 5. 위치 거부·낮은 정확도·오래된 위치

- **문제:** 위치 권한이 없거나 오차가 큰 상태에서 출발지가 정확한 것처럼 경로를 요청할 수 있다.
- **원인:** 브라우저별 권한과 기기 센서 정확도가 다르고 한 번 얻은 위치는 시간이 지나면 달라질 수 있다.
- **해결방법:** 사용자 버튼에서만 위치를 확인한다. HTTPS 여부·권한 거부·시간 초과를 설명하고 100m 초과 오차는 경로 출발지로 쓰지 않는다. 2분 이상 된 위치는 경로 요청 전에 다시 확인한다.
- **결과:** 모의 권한 거부·400m 오차 테스트에서 경로 요청을 수행하지 않고 재시도 안내를 표시하는 것을 확인했다. **휴대폰 실외 센서 검증은 남아 있다.**

## 6. 늦게 도착하는 응답이 새 화면을 덮어쓸 수 있음

- **문제:** 검색어를 지우거나 다른 화면으로 이동한 뒤 과거 검색 결과가 나타날 수 있다.
- **원인:** 네트워크 요청과 위치 콜백의 완료 시점이 화면 전환보다 늦을 수 있다.
- **해결방법:** 검색·경로 요청을 취소하고 위치 콜백에 요청 순번을 적용했다. 화면을 떠나면 미완료 결과를 반영하지 않는다.
- **결과:** 지연 검색을 보낸 뒤 검색어를 지웠을 때 이전 결과가 다시 표시되지 않는 테스트를 통과했다.

## 7. 로컬 Vite만 실행하면 서버 API가 없음

- **문제:** 정적 Vite 화면만으로는 서버 비밀 키를 사용하는 경로 API가 실행되지 않는다.
- **원인:** Vite 개발 서버와 Vercel Functions 실행 환경이 다르다.
- **해결방법:** 동일한 Web Request/Response 처리 함수를 Vite 미들웨어와 Vercel API 진입점에서 공유했다. API와 프론트엔드를 같은 주소로 요청한다.
- **결과:** 키 없는 개발 서버의 실제 `/api/navigation?action=config` 응답을 브라우저에서 확인했다. TypeScript 검사에 서버·Vite 설정·API도 포함했다. **Vercel 실제 배포는 아직 수행하지 않았다.**

## 8. 지도 SDK 실패가 전체 화면 사용을 막음

- **문제:** 지도 스크립트가 차단되거나 키가 없으면 지도 컨테이너가 비어 보일 수 있다.
- **원인:** 네트워크·지도용 키 설정은 검색 API와 별개다.
- **해결방법:** 지도 키 미설정 안내, 스크립트 시간 제한, 재시도 버튼을 추가했다. 지도 로딩 실패와 경로 조회를 분리해 거리·시간 정보는 유지한다.
- **결과:** 지도 스크립트 차단 테스트에서도 경로 총계와 다시 불러오기 버튼이 표시되는 것을 확인했다.

## 검증 범위

- 자동화된 서버·데이터 테스트와 모의 API·모의 위치·모의 지도 SDK 브라우저 테스트를 사용한다.
- 실제 TMAP API를 호출한 성공 결과나 실제 지도 표시 결과는 아니다.
- 모든 추가 수정·검증 결과는 아래 실행 기록에 갱신한다.

## 9. 실제 검색 홈에서 한옥 그림과 검색창이 잘림

- **문제:** 모바일 화면 캡처에서 실제 검색 홈의 처마 일러스트가 사라지고 검색창 아래가 잘렸다.
- **원인:** 스크롤 컨테이너를 세로 flex로 구성하면서 홈 상단에 기본 `flex-shrink: 1`이 적용되어 내용이 긴 설정 안내에 밀려 축소됐다.
- **해결방법:** 실제 홈의 상단과 본문에 `flex-shrink: 0`을 적용해 의도한 높이를 유지하고 전체 내용은 스크롤하도록 했다.
- **결과:** 키 미설정 홈을 다시 캡처해 검색창·처마·설정 안내가 잘리지 않는 것을 확인했다.
