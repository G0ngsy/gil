# 실기기 보고: OCR 오인식과 GPS 도로 반대편 표시

확인일:2026-11-27. 상태: **현장 실패 보고 확인, 미해결**. 코드 검토 기준4381493. 영상의 실제 배포 커밋/기기 모델/브라우저 버전은 확인하지 못했다.

## 문제
사용자는 실제 촬영 사진에서 글자가 읽히지 않았고, 지도 표시 위치와 달리 실제로는 반대편 도로에 있었다고 보고했다.

## 원인
### 확인한 사실
- 사용자 제공 영상 KakaoTalk_20261127_102803819.mp4(약62.5초)를 로컬 Chrome으로 읽어 장면을 추출/확인했다. 원본 영상/위치가 보이는 프레임은 저장소에 추가하지 않았다.
- 영상은 이미 OCR 진행 화면에서 시작한다. 약6.3초 장면에서 의미 없는 한영 혼합 문자열/기호가 다수 선택 항목으로 표시된다. 작업 실패 화면이 아니라 텍스트가 반환된 뒤 이를 유효한 후보처럼 나열한 상태다.
- 현재 recognizedLines는 공백/길이/중복만 정리하며, 인식 품질을 판정하지 않는다. 워커도 결과의 text만 전달하므로 낮은 신뢰도의 인식 결과를 구분하지 못한다.
- 영상의 약43.8초 지도 장면에는 현재 위치 핀과 ‘GPS 오차 약5m’가 표시된다. 실제 반대편에 있었다는 것은 사용자의 현장 보고이며 영상만으로 실측 좌표·도로 횡단 오차를 산출할 수 없다.
- 현재 getUserPosition은 기기가 보고한 정확도가30m 이내이면 첫 표본을 바로 채택한다. 이 수치는 실측 오차 검증이 아니다. 지도에 보이는5m도 실제 위치가 반드시 그 반경에 있다는 보장이 아니다.

### 아직 확인하지 못한 원인
OCR에 넣은 원본 사진/화소 크기/글자 크기/촬영 방향이 영상에 없다. 전체 풍경의 작은 글자·흐림·기울기·반사·배경·언어/분할 방식 중 어느 요인이 주원인인지 확정할 수 없다. 현재 전체 사진을 긴 변2048px로 축소하고 기본 문서 분할 방식으로 읽는 점은 개선 후보다.
GPS도 원시 위치 표본/시각·실제 서 있던 지점의 기준 좌표가 없어서 기기 추정 편향/주변 환경/지도 또는 마커 표시 해석을 분리해 재현하지 못했다. 임의로 도로 반대쪽이나 가까운 경로로 좌표를 옮겨 해결했다고 주장하지 않는다.

## 해결방법
**아래는 제안이며 이번 기록 작업에서 앱에 적용하지 않았다.**
1. 원본 촬영 사진을 같은 엔진에 넣어 기준 실패를 재현하고, 전체 사진과 글자 영역 선택/확대·회전·장면용 분할 방식의 결과를 비교한다. 입력 없이 개선 성공이나 인식률을 만들어내지 않는다.
2. OCR의 신뢰도/단어·줄 결과를 활용해 품질이 낮을 때 ‘정확히 읽지 못했어요’와 재촬영·글자 영역 선택·직접 입력을 보여준다. 판단 기준은 원본 실패/정상 사진으로 검증하며 기호를 일괄 삭제해 정답으로 꾸미지 않는다.
3. 앞서 제안한 지도/주소 확인→맞는지 사용자 확인→다시 위치 확인/사진으로 주변 대조 흐름을 후속 구현 대상으로 둔다. GPS 점과 사진에서 찾은 건물은 구분하고 건물 중심점을 사용자 GPS에 대입하지 않는다.
4. 지도 오차 문구는 기기가 제공한 추정값임을 구분하고, 도로 어느 편인지 확인했다고 오해하게 하지 않는다. 추가 위치 수신도 지점 정확성을 보증하지 않는다.

## 결과
사용자 영상과 현재 코드/공식 자료의 대조를 완료했다. 현장 OCR 실패와 GPS 반대편 보고를 기존 합성 이미지/모의 GPS 성공과 구분해 포트폴리오 상태에 반영했다. 이 작업은 원인 조사/문서 기록이며 앱 코드·GPS 정책·OCR 알고리즘을 변경하지 않았다. 빌드/자동 테스트는 재실행하지 않았고 수정 완료/정확도 개선/실기기 성공으로 표시하지 않는다. AI 지원 분석/기록.

추가 재현에 필요한 자료: OCR에 사용한 원본 사진. 단순 화면 녹화 프레임을 원본 촬영 사진으로 대체하지 않는다.

공식 참고: [Tesseract 품질·분할 안내](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html), [W3C Geolocation](https://www.w3.org/TR/geolocation/). 전자는 글자 영역/기울기/분할 방식이 결과에 영향을 준다고 설명한다. 후자는 브라우저가 제공하는 정확도 반경을 정의하며 현장 지점의 실측 증명과는 다르다.
