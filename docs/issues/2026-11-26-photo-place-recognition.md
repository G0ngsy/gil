# 사진 주변 장소 확인 구현과 검증

## 문제
현재 웹앱에는 간판 사진에서 장소를 찾는 기능이 없었다. 사용자는 확정 계획 저장, 기능별 한국어 주석, 홈에서 사진 화면으로 푸시 전환을 요청했다.

## 원인
기존 카메라는 GPS 경로 안내 영상 표시용이었다. 사진 입력/OCR/확인용 후보 상태가 없고, Tesseract 초기화가 끝난 뒤에야 작업자 종료 함수를 얻으면 초기화 중 취소를 처리하기 어려웠다.

## 해결방법
- [확정 계획](../plans/photo-place-recognition.md)을 저장했다. 홈 현재 위치 카드 아래 보조 버튼→사진 확인 화면을 추가하고 기존0.3초 push-forward/back과 reduced motion/브라우저 기록을 재사용했다.
- 사진 입력→미리보기→명시적 글자 읽기→읽은 줄 다중 선택/수정→GPS 주변 또는 지역명 검색→후보 선택→확인 완료. GPS/목적지/진행 경로와 연결하지 않고 확인 화면 안의 상태로만 사용한다.
- Tesseract.js6.0.1, lockfile 코어6.1.2, kor/eng1.0.0의4.0.0_best_int 자료를 사용한다. predev/prebuild가 node_modules에서 public/ocr/v1로 실행 파일·모델·라이선스·버전 자료를 복사한다. 사진/원문은 서버에 보내지 않고 명시적으로 확인한 검색어/필요한 위치만 기존 API로 보낸다.
- 바깥 전용 작업자가 Tesseract 하위 작업자를 생성하도록 하여 초기화 중에도 즉시 종료한다. 정상/오류/취소/90초 상한에서 정리하고 화면 숨김/이탈은 작업을 취소한다. 사진 선택기의 숨김은 선택된 파일을 복귀 후 처리하는 흐름과 구분한다. 세대 번호와 AbortController로 늦은 OCR/검색 응답을 무시한다.
- JPEG/PNG/WebP10MB, 긴 변2048px로 비율 유지 축소, 이미지 오류/빈 결과/네트워크 실패/후보 없음/직접 입력과 취소를 처리한다. 말줄임 후 중복 줄을 제거하고 키보드 초점/큰 글씨/줄바꿈을 지원한다.
- 새 기능의 역할·흐름·데이터 경계·자원 정리에 한국어 주석을 작성하고 새 파일을 읽기 쉽게 정렬했다. 이용 안내의 ‘사진 기능 없음’을 현재 동작과 자료 캐시 설명으로 갱신했다.

## 결과
- 빌드 통과, 기본 단위141개 통과. 기존 검색/위치/브라우저 기록/안내 유지와 사진 기능을 포함한 브라우저46개 통과. 최종 자원 정리 보완 후 사진9개 재통과(중복 포함).
- 실제 Tesseract·실제 한글/영문 모델로 브라우저 Canvas의 합성 간판 ‘수협은행 / 서현역지점 ATM’을 인식했다. 같은 서비스에서만 엔진/언어 파일을 요청하고 검색 전 API 호출 없이 글자 확인 화면을 표시했다. 잡음 줄도 나와 사용자 확인/수정이 필요했다. 실제 현장 간판 인식률/휴대폰 처리 시간으로 해석하지 않는다.
- 실제 엔진 초기화 요청을 대기시킨 상태에서 CDP로 부모/하위 작업자2개 이상 생성→취소 후0개를 확인했다. 코어 요청 실패도 재시도 화면으로 돌아온다.
- 360/390/430px 푸시 ready/역방향 복귀·사진/검색/후보·자동 위치/카메라 권한 요청 없음·저장 없음,360×640/200% 글씨, 취소/뒤로가기/화면 숨김/지연 검색을 확인했다. 사진 화면 왕복이 기존 목적지/복원 경로/GPS 감시를 바꾸지 않았다.
- 실제 OCR 캡처와 후보 확인 캡처를 시각 검토했다. [실제 엔진·합성 입력](../portfolio/assets/2026-11-26-photo-place-real-ocr-390.png), [모의 검색 후보 확인](../portfolio/assets/2026-11-26-photo-place-confirmed-390.png).
- 실제 기기 촬영 선택기·Samsung Internet/설치 PWA·야간/흐림/반사 사진·실제 보행/방위 정확도는 미확인. 로컬 검색 API/GPS는 모의 입력이고, 운영 TMAP·배포 검증은 후속 기록으로 구분한다. AI 지원 구현·검증·문서.

### 작업 중 확인한 오류
첫 자료 준비 빌드에서 npm 패키지 LICENSE 파일명을 잘못 가정해 실패했다. LICENSE.md와 각 번들 고지/코어/언어 자료 원문을 복사하도록 고쳤다. 처음 모의 OCR 테스트에서 줄바꿈 문자열이 유효하지 않은 작업자 코드로 생성되어 실패했다. JSON.stringify로 테스트 데이터만 정확히 인코딩한 뒤 실제/모의 경로를 분리해 재검증했다. 제품 실패를 감추려고 실제 엔진을 모의 결과로 대체하지 않았다.

운영 확인: 제품5e8a712의 배포31WmiLXVePAYZnzXmBocud65wcPz success. 실제 OCR/모델과 합성 서울도서관 간판→실제 TMAP 검색200/후보17개→선택→푸시 역방향 복귀/홈 GPS 불변/페이지 예외0. GPS만 공공 좌표 주입. [배포 기록](../deployment.md). 실기기/현장 사진 정확도 검증과 구분한다.
