# 카메라 안내를 GPS 경로 행동 표시로 단순화

## 문제
사용자는 카메라 위 고정 화살표만 원했으나 기존 구현이 WebKit 방위/오차와 휴대폰 수평 자세를 요구해 갤럭시 사용에 제약이 있었다. 사용자가 계획을 재검토하고 방향 센서 없이 구현·모의 검증 및 실행 화면 확인을 요청했다.

## 원인과 재점검
카메라 영상 배경, 경로상 다음 행동, 휴대폰/시선의 방향을 한 기능에서 다루고 있었다. 경로 행동을 알려주는 목적에는 휴대폰 방위가 필요하지 않다. 대신 GPS만으로 정지 사용자의 시선을 알 수 없다는 제한을 분명히 해야 한다. 이미 지도에서 경로 진행·회전 코드·안내점 거리를 계산하므로 같은 카드를 사용해 일치시킨다. 확인되지 않은 직진·좌우를 새로 추정하지 않는다.

## 해결방법
LiveCameraGuide의 방위 훅/진북 비교/센서 버튼/진단/자세 조건을 제거하고 지도 JourneyInstruction을 재사용했다. 지도와 동일한 경로 진행·최신 GPS 오차·이탈·도착·중단 상태를 전달한다. 카메라는 영상 배경이며 고정 아이콘/짧은 문구만 표시한다. 실제 도로·시선 방향을 가리키거나 지면에 붙는 AR이 아님을 화면에 알린다.

도착/자동 수신 중단 시 카메라를 즉시 분리하던 상위 조건을 바꿔 상태를 계속 볼 수 있게 했다. 카메라 닫기·지도 복귀·안내 종료·탭 숨김의 영상 해제는 유지한다. 방위 실험은 검토용 시뮬레이션에만 남는다. 일반 카메라 화면에 모의 입력은 넣지 않았다.

## 검증과 화면 확인
- 단위120개 통과, 빌드 통과.
- 카메라/세션/기존 영상 브라우저23개 통과. 공통 지도/카메라9개 재통과. 좌회전/유턴 검증 추가 후 최종 카메라6개 결과는 아래 기록.
- 360/390/430px 직진→회전 접근→지금 회전→회전 후 다음 단계→2표본 도착, 방향 권한 호출0, 영상 해제, 이탈·GPS45m·오래된 GPS·수신 중단에서 화살표 숨김을 확인한다. 지도 복귀 후 같은 안내 행동/상태를 비교한다.
- 로컬 휴대폰 크기 Chrome에서 canvas 모의 영상·공공 좌표 GPS·모의144m 경로를 주입해 약16초 영상을 녹화했다. 화면에 모의 입력임을 명시한다. 실제 카메라/실외 GPS/실제 TMAP 검증이 아니다.
- 녹화 확인에서 도착 카드가 지도 장식용 flex-wrap을 상속해 옆으로 잘린 것을 발견했다. 카메라 도착 장식을 제외하고 폭/줄바꿈을 보완했다. 도착 후 가로 넘침 검사를 세 크기에 추가하고 최종 영상/도착 화면을 재생성했다.
- Android 에뮬레이터 실행 파일을 PATH 및 일반 SDK 위치에서 찾지 못했다. Android OS를 구동한 것으로 표현하지 않는다. 브라우저 모바일 에뮬레이션으로 실행했다.
- 첫 녹화는 FFmpeg 미설치, 다음은 인트로 대기 조건으로 실패했다. Playwright 녹화 도구 설치·동작 감소 설정으로 보완했다. 마지막 표시 창 종료로 중단된 녹화는 headless 재실행해 최종 자료와 구분했다. 녹화 도구 설치는 로컬 도구이며 제품 의존성을 변경하지 않았다.

## 제한/다음
실기기 카메라 권한·후면 렌즈·영상/GPS 동시 동작과 실외 경로 품질을 별도 확인해야 한다. 휴대폰을 반대로 보고 서 있는 상태를 감지하지 않으며 지면 고정 AR·시선 방향은 이번 기능이 아니다. 푸시와 실제 배포 확인을 구분한다.

기준1263907 이후 작업, AI 지원 설계 재점검·구현·자동 검증·시연 녹화·문서. 재현 명령과 자료는 [사용 안내](../camera-setup.md), [포트폴리오 근거](../portfolio/evidence.md)에 기록한다.

최종 결과: 카메라6개(좌회전/유턴 포함) 모두 통과, 최종 빌드 통과. 앞선 관련23개·지도/카메라9개와 중복을 제외하면 관련30개 범위를 다뤘다. 최종 카메라6개는 마지막 추가 검증 이후 실행했고 전체 브라우저 모음을 재실행한 것은 아니다. 영상 페이지 예외0, 최종 우회전/도착 캡처 직접 확인. 문서 링크296개·변경 형식 검사 통과. React 검토에서 공통 안내 재사용·불필요 센서 구독 제거·최신 GPS/상태 전달·영상 해제·접근성 상태 안내를 확인했다.
