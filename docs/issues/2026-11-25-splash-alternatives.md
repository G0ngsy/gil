# 서로 겹치지 않는 새 스플래시 두 안

## 문제
기존 문/수묵/등불과 다른 두 시작 연출을 각각 재사용 가능하게 구현해야 했다. 기존 Intro는 세션 저장과 4.55초 재생을 사용하므로 이번 localStorage/2.5~3초 요구와 달랐다.

## 원인
기존 문 연출을 확장하면 새 컨셉과 섞이고, 부모가 다시 그려질 때 콜백에 의존하는 타이머는 재시작될 수 있다. 첫 방문 저장을 필수 기능처럼 처리하면 저장 차단 시 홈 진입이 막힐 수 있다.

## 해결방법
매듭 조합과 세 걸음을 별도 Splash.tsx/CSS로 만들었다. 둘 다 2.8초의 transform/opacity 중심 애니메이션이며 마지막 중앙 로고/문구를 거쳐 홈을 드러낸다. 공통 키 splashSeen, 최신 콜백 ref, 완료 중복 방지 ref, useEffect 타이머/설정 구독 정리, 저장 실패 허용을 사용한다. 실제 버튼으로 전체 화면 탭과 키보드를 지원하고 동작 줄이기는 초기 렌더부터 숨기며 재생 중 변경도 즉시 종료한다. App에서 하나만 선택하며 기본 매듭, 두 비교 URL, 별도 기존 문 URL을 분리한다. 로컬 폰트의 name 테이블을 읽어 Noto Serif KR/Noto Sans KR임을 확인했다.

## 결과
빌드·기본 테스트 137개 통과. 새 연출/기존 문/기본 진입/홈 위치 개선/설치 흐름의 관련 브라우저 32개 통과. 발자국 모양 최종 조정 후 빌드 및 새 연출 12개 재통과. 초반 통합 실행은 이전 서버 포트 점유로 시작되지 않았고, 포트가 정리된 것을 확인 후 재실행했다. StrictMode에서 unmount 후 콜백/저장 없음, 콜백 변경에도 총 시간 유지, 중복 완료 방지, 360/390/430px, 저장 유지/차단, 동작 줄이기, 단독 연출을 검증했다. 실기기 프레임 속도는 측정하지 않았다. 지도/API/GPS는 이번 변경 범위가 아니다. 컨셉·SVG·주석·테스트는 사용자 요청에 따른 AI 지원 구현이다.
