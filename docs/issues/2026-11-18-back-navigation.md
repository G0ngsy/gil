# 뒤로가기 흐름 연결 (2026-11-18)

## 문제
실제 화면은 React 상태로만 바뀌어 브라우저/휴대폰 뒤로가기가 화면 이동 순서를 알지 못했다. 상단 뒤로가기도 경로 확인만 검색으로, 나머지는 홈으로 보내 실제 직전 화면과 달랐다.

## 원인
History API 방문 기록과 화면 상태가 분리돼 있었고 카메라·종료 확인창은 본문 화면과 별도 상태였다. 카메라 닫기 알림은 정리/상태 변경 때 반복될 수 있어 단순히 매번 history.back을 호출하면 두 화면을 건너뛸 수 있었다.

## 해결방법
- 실제 화면의 방문 기록을 브라우저 history에 연결하고 상단 버튼도 같은 back 동작을 사용한다. 지도→경로 확인→검색→홈, 기록에서 검색→뒤로가기→기록 등 진입 순서를 따른다.
- 카메라와 종료 확인창도 별도 방문 단계로 관리한다. 카메라 뒤로가기는 영상만 해제하고 지도/GPS 안내는 유지한다. 확인창 뒤로가기는 종료를 취소한다.
- 중복 뒤로가기 요청을 이동 완료 전 차단한다. 홈으로 기록을 정리하는 중 새 화면 요청은 대기 후 반영한다.
- X/안내 종료는 홈까지 기록을 정리한다. 종료·새로고침 전의 낡은 방문 기록이나 앞으로가기로 카메라/종료된 안내를 되살리지 않는다. 카메라 시작은 사용자 버튼에서만 허용한다.
- 뒤로 이동 시 진행 중 검색/위치 확인/재탐색/복원 요청을 취소하고 늦은 응답을 무효화한다. GPS 안내 세션은 명시적 종료 외에는 유지한다.
- 홈에서는 뒤로가기를 가로채거나 가짜 화면을 추가하지 않는다. 웹에서 탭/앱 종료를 강제하지 않으며 이전 페이지 복귀·설치앱 이탈은 브라우저/OS 기본 동작을 따른다.
- 기존 예시/센서 시뮬레이션은 검토용으로 유지하며 이번 History 연결 대상은 기본 실제 앱이다.
