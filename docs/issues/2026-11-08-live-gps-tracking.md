# 실제 GPS 연속 수신 테스트 연결 (2026-11-08)

## 문제
모의 좌표로만 이동을 검증할 수 있어 실제 브라우저 GPS의 권한·수신·해제 흐름을 확인할 수 없었다.

## 원인
일회성 현재 위치 조회만 있었고, 추적 세션과 늦게 도착하는 콜백·수신 중단을 관리하는 처리가 없었다.

## 해결방법
- `/?mode=simulation`에 선택형 실제 GPS 추적 시작·중지 버튼을 추가했다. 시작할 때만 권한을 요청하고 기존 진행을 초기화한다.
- `useGpsTracking`이 `watchPosition` 수신 좌표를 기존 경로 진행 계산에 전달한다. 실제 GPS 동작 중 모의 입력을 잠가 두 좌표원이 섞이지 않도록 했다.
- 중지·도착·탭 숨김·pagehide·컴포넌트 해제에서 `clearWatch`와 타이머 해제를 수행한다. 세션 번호로 과거 콜백을 무시한다. 자동 재시작하지 않는다.
- 권한 거부·위치 사용 불가·시간 초과·동기 예외를 처리한다. 유효한 수신이 20초간 없으면 추적을 중지한다.
- 오차 30m 초과·10초보다 오래된 위치·1초 넘게 미래인 위치·잘못된 좌표는 진행에 반영하지 않는다.
- 실제 GPS 수신 테스트도 서울시청 인근의 고정 예시 경로를 사용한다는 문구를 표시한다. 실제 목적지 길찾기가 아니며 위치를 서버로 전송하거나 저장하지 않는다.

## 결과
- 검증: 단위 테스트 27개와 TypeScript 검사·프로덕션 빌드 통과.
- 브라우저 결과: 기존 모의 GPS 및 실제 GPS 시작·중지·재시작·단계·이탈·복귀·도착·늦은 콜백 무시·권한/수신 오류·수신 중단·탭 숨김·화면 종료·시안 복귀를 검증한다. 추적 브라우저 테스트 9개 모두 통과했다.
- 미확인: 실기기 GPS 수신·실외 보행은 수행하지 않았다. 브라우저 테스트는 위치 콜백을 주입해 제어 흐름을 검증한다.
- 보류: TMAP 키·실제 경로 조회·재탐색 API 연동. 실제 검색 모드에는 아직 연속 추적을 연결하지 않았다.
- 제한: 교차·중첩 경로의 단계 모호성과 GPS 순간 이동 판정 보강은 후속 작업이다. 이번 작업은 GPS 수신 수명 관리와 예시 경로 연결에 한정한다.

## 확인 방법
HTTPS 또는 localhost의 `/?mode=simulation`에서 실제 GPS 추적 시작을 선택한다. 중지 후에만 모의 좌표를 입력할 수 있다. 탭을 숨겼다가 돌아와도 자동으로 재시작하지 않으며 시작 버튼으로 재개한다. 예시 경로와 먼 곳에서는 이탈 표시가 정상이다.
