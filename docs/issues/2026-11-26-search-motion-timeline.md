# 검색·기록 전환과 경로 타임라인

## 문제
사용자가 장소 목록 페이드업, 최근 검색어 또는 자동완성, 카드 확장 전환, 기록 상세 푸시 전환, 전체 경로 타임라인을 요청했다. 기존은 검색 기록을 상세 화면에서만 볼 수 있었고 화면은 즉시 교체, 경로 상세는 일반 목록이었다.

## 원인
화면 방문 기록과 시각적 전환을 연결하는 계층이 없었다. 전환을 위해 페이지를 중복 마운트하면 GPS·카메라 세션이 영향을 받을 수 있으며 비동기 전환 중 빠른 뒤로가기는 이전 화면 갱신이 늦게 적용되는 위험이 있었다.

## 해결방법
- 홈/검색 결과 입력창 focus 시 최근 검색어 최대5개를 보여주고 입력값으로 저장 기록을 필터링한다. 선택·개별 삭제·Escape·Tab/Enter를 지원한다. 입력만으로 외부 API를 호출하지 않으며 선택/제출 시 기존 주변/전국 검색을 사용한다. 실제 장소 자동완성 API를 새로 제공한 것은 아니다.
- 장소 목록은320ms 페이드업, 항목별35ms 지연(최대210ms)으로 표시한다. 경로에서 돌아올 때는 재등장 연출을 생략해 공유 카드와 충돌하지 않게 했다.
- 화면 기록의 실제 상태 갱신은 한 번만 실행한다. View Transition API 지원 환경에서는 선택 카드와 경로 화면을 같은 이름으로 연결해360ms 확장, 홈↔기록은300ms 좌우 전환을 사용한다. 빠른 다음 이동은 이전 갱신을 먼저 확정한 뒤 이전 연출을 정리한다. unmount 시 늦은 콜백과 연출을 취소한다.
- 미지원/시작 실패는 간단한 등장으로 대체하며 동작 줄이기는 움직임 없이 이동한다. 지도/GPS/카메라를 연출용으로 복제하거나 재시작하지 않는다.
- 전체 경로는 출발점→실제 안내 단계/제공된 도로명→경로 도착점의 세로 타임라인이다. 없는 구간 시간/거리/현재 단계는 만들어내지 않으며 빈 상세는 안내가 없다고 표시한다.

## 결과
빌드·기본 테스트 통과. 새 흐름과 기존 검색/기록/뒤로가기/GPS 세션/지도/위치 관련 브라우저66개 통과. 실제 네이티브 전환 ready 완료까지 확인하는 최종8개 재통과. 360/390/430px, 최근 검색 필터/삭제/키보드, 입력 중 API 호출 없음, 선택 카드 확장, 기록 push/pop, 빠른 Back, API 미지원/시작 실패, 동작 줄이기, 빈/실제 단계 타임라인을 확인했다. 초기 애니메이션 검사는 기본 reduce 설정 때문에 실패했고 새 연출 검사의 환경을 no-preference로 분리해 해결했다.

API/GPS/SDK는 이 검증에서 모의 응답/공개 테스트 좌표를 사용했다. 실외 정확도 또는 실기기 FPS 검증은 아니다. 사용자 요청에 따른 AI 지원 구현이다. 캡처 assets/2026-11-26-recent-search-390.png, route-timeline-390.png는 모의 데이터 화면이다.
