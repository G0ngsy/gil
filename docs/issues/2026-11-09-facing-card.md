# 테스트 화면 방향 안내 카드 연결 (2026-11-09)

## 문제
경로·휴대폰 방향 계산과 채팅 시안은 있었지만 실제 앱의 테스트 화면에는 화살표·문구와 모의 방향 조작이 없었다. 판정이 흔들릴 때 문구가 계속 바뀌거나, 불확실한 상태에서 지난 화살표가 남을 수 있었다.

## 원인
계산 결과와 안정화된 표시 상태를 분리하는 화면 계층이 없었고, 실제 GPS 테스트와 모의 방향 입력의 사용 범위가 정해져 있지 않았다.

## 해결방법
- `/?mode=simulation`에 `FacingGuide`를 추가했다. 모의 GPS 좌표를 받은 뒤 정방향·왼쪽·오른쪽·반대·확인 불가 버튼 또는 방위각/오차 숫자를 입력할 수 있다. 기존 `compareFacing` 계산을 사용하고 경로 꺾임에서도 마지막으로 선택한 모의 휴대폰 방위를 유지해 비교한다.
- 카드 하나에 청록색 화살표와 문구를 계속 표시한다. 새 유효 상태가 800ms 유지되면 전환하고, 중간에 다른 판정이 들어오면 대기 타이머를 취소한다. 동일 상태에는 카드 재생성·팝업·사라짐 타이머를 사용하지 않는다.
- 확인 불가는 즉시 렌더 단계에서 방향 화살표를 숨긴다. 이탈·거부된 위치·도착·안내 종료에도 방향 지시를 유지하지 않는다. 경로·좌표원·안내 세션 변경 시 카드 입력과 전환 타이머를 초기화한다.
- 실제 GPS 모드에서는 모의 방향 카드를 대기 상태로 두고 조작을 잠근다. 방위 센서가 연결된 것처럼 보이지 않게 ‘모의 방향 · 실제 방위 센서 미연결’을 표시한다. 위치·기기 방향 권한을 새로 요청하지 않는다.
- 모의값은 변경 전까지 유지되는 입력이다. 이 테스트 화면에서만 마지막 모의 GPS 위치와 방위에 같은 모의 현재 시각을 사용한다. 실제 센서의 오래된 값 검사나 신뢰도를 우회하는 연결로 사용하지 않는다. 향후 실제 센서 연결에서는 원래 표본 시각·정확도를 전달해야 한다.
- 선택 버튼의 `aria-pressed`, 숫자 입력 이름, 카드의 `aria-live=polite`를 제공한다. 방향/문구를 반복 애니메이션하지 않고 동작 감소 설정에서도 동일하게 사용할 수 있다. 기존 아이콘 체계에 돌아서는 화살표만 추가했다.

## 결과
- 단위 테스트 88개 통과. 새 계산 함수를 중복 작성하지 않아 단위 테스트 수는 유지된다.
- 첫 브라우저 실행: 방향 카드 7개 + 기존 추적 19개, 총 26개 통과.
- 선택 표시와 도착 검증 보완 뒤 방향 카드 7개 최종 재검증 통과.
- TypeScript 검사·Vite 프로덕션 빌드 최종 통과. 390px 최종 캡처를 열어 화살표·문구·선택 버튼을 육안 확인하고 포트폴리오 자료로 보관했다.
- 360·390·430px 가로 넘침과 상태별 문구/화살표, 799/800ms 경계, 짧은 흔들림, 확인 불가의 즉시 숨김, 꺾임·이탈·복귀·종료, GPS 선택·경로 변경을 검사했다.
- 미확인: 실제 방위 센서, 진북/자북 및 기기 축 변환, 휴대폰 실외 정확도·몸 방향, TMAP·카메라/AR 연결. 최신 코드의 원격 배포도 이번 작업 범위가 아니다.

## 확인 방법
`/?mode=simulation` → ‘출발’로 모의 GPS 전송 → ‘모의 방향 안내’에서 방향 선택. 문구는 유지되고 새 방향은 약 0.8초 뒤 반영된다. ‘확인 불가’나 큰 오차에서는 즉시 화살표가 숨겨진다. 실제 GPS 테스트를 선택하면 이 모의 방향 조작은 잠긴다.
