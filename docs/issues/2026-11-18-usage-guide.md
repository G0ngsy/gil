# 개인정보·이용 안내 (2026-11-18)

## 문제
권한·영상 비저장 안내가 여러 화면과 개발 문서에 흩어져 있었다. 안내 복원 도입 후 경로 좌표는 기기에 저장되므로 ‘좌표·경로를 저장하지 않는다’는 이전의 포괄적 설명을 그대로 사용하면 오해할 수 있었다.

## 원인
최근 검색 기록과 진행 중인 안내 복원이 서로 다른 저장소/보관 기준을 사용한다. 서버를 통한 TMAP 요청과 브라우저 지도 SDK 요청도 구분해 설명하는 화면이 없었다.

## 해결방법
- 홈 하단에 ‘개인정보·이용 안내’를 추가하고 기존 방문 기록/뒤로가기/본문 초점 이동과 연결했다.
- 위치를 사용하는 동작, 카메라/마이크 권한, 권한 거절 시 가능한 기능과 화면 이탈 중지 방식을 설명한다. 같은 앱 안의 홈 이동은 안내 종료가 아니라는 점을 구분한다.
- 최근 기록10개씩·복원용 목적지/경로 좌표/저장 시각·하루 이내 복원/만료 시 다음 실행 정리·탭 연출 상태·정적 오프라인 안내를 설명한다.
- 경로 좌표는 위치 정보임을 명시하고 실시간 GPS 관측 목록/이동 이력·카메라 영상 비저장과 구분한다.
- 검색어·주변/주소/경로 좌표·목적지 식별 정보가 길빛 서버(Vercel)를 거쳐 TMAP에 전달되는 흐름과 지도 SDK의 직접 접속을 설명한다. 제공사 접속 정보 보관 기간을 임의로 확정하거나 ‘어디에도 저장되지 않는다’고 표현하지 않는다.
- 최근 기록 관리 버튼과 개별/전체 삭제, 홈의 복원 삭제, 진행 안내 종료, 브라우저 사이트 데이터/권한 관리 방법을 제공한다. 기기 삭제와 이미 전달한 제공사 요청은 구분한다.
- 현재 카메라 안내의 AR 한계와 출입구 확인·오프라인 제약을 설명한다. 안내 열기 자체는 권한·외부 API 요청·기록 삭제를 실행하지 않는다.
- 최근 기록 문서의 좌표 비저장 표현도 복원 경로 저장과 구분하도록 정정했다.

## 결과
빌드·단위133개·관련 브라우저29개 통과. 안내/기록 관리/큰 글씨와 기존 뒤로가기·복원 검증을 포함한다. 기존 GPS 세션 유지 검사와 최종 배포 결과는 아래 추가한다. 모의 GPS/API/권한 검사이며 실제 기기 권한 설정 UI는 미확인이다. AI 지원 구현·문구 대조·검증·문서화.

## 출처와 범위
구현 코드 client.ts/server/navigation.ts/history.ts/savedGuidance.ts/CameraPreview.tsx/Intro.tsx/public/sw.js를 대조했다. 제공사 링크는2026-11-18 공개 확인: TMAP 공식 사이트 https://www.tmapmobility.com/ (개인정보 안내 메뉴), Vercel https://vercel.com/legal/privacy-notice (기존 privacy-policy 주소에서 이동). 제공사 정책을 길빛의 실제 보관 기간으로 단정하지 않는다. 이 화면은 현재 기능 이용 설명이며 운영 주체/문의처/실제 제공사 계약·로그 보관 설정이 확정된 정식 운영 정책의 완성이나 법률 검토 완료를 의미하지 않는다. 확인되지 않은 연락처나 보관 기간은 만들지 않았다.

로컬 검증: 빌드·단위133개·기존 흐름 포함 브라우저29개 통과. 기존 GPS 세션 유지 검사 추가 후 안내 관련6개 통과(앞선5개와 중복),390px 캡처 검사1개 재통과. 서로 다른30개 시나리오이며 합산 실행 수를 별도 성과로 해석하지 않는다. [모의 화면](../portfolio/assets/2026-11-18-usage-guide-390.png). 실제 사용자 위치·영상은 사용하지 않았다. 배포 확인은 별도 기록한다.
