# 글자 영역 선택과 위치 확인 보완

날짜: 2026-11-27. 기준: adcf3b7 이후 작업. 상태: 구현·로컬 검증 완료, 현장 정확도 미확인.

## 문제
현장 영상에서 글자가 의미 없는 문자열로 반환됐고 실제 사용자는 GPS 점의 반대편 도로에 있었다고 보고했다. 원본 촬영 사진은 남아 있지 않다. 전체 풍경을 바로 읽으면 사용자가 읽을 글자를 지정할 수 없다.

## 원인
기존 사진 전처리는 전체 사진을 먼저 2048px로 줄였다. 작은 글자가 줄어들 가능성이 있지만 원본 없이 이번 실패의 직접 원인으로 확정하지 않는다. OCR 줄 정리는 품질을 판정하지 않는다. 기기가 제공한 정확도도 도로 어느 편인지 확인한 결과는 아니다.

## 해결방법
- 원본 파일·화소 크기를 메모리에 보관하고 드래그로 글자 영역을 지정한다. 반대 방향 드래그·전체 선택·선택 지우기·키보드 슬라이더를 제공한다. 선택 전에는 읽기 버튼을 비활성화한다.
- 원본 좌표에서 선택 부분만 자른 후 긴 변2028px 이하로 줄이고 흰 테두리10px를 더한다. 출력은 최대2048px, JPEG 품질0.92다. 사진 교체/취소/화면 이탈 시 URL·작업자·요청을 정리한다.
- 기존 내 위치 확인 화면(3f5aac0)을 재사용한다. GPS와 사진 속 장소는 별도 표시하고 사진 좌표를 GPS로 대입하지 않는다. 기기 추정 오차와 도로 어느 편인지 확인하는 문구를 표시한다.
- 2분 넘은 위치는 마지막 확인 위치로 표시하고 확정을 막는다. 다시 조회 후 확정할 수 있다. 이 시간은 신선도 정책이며 위치 정확성을 보장하지 않는다. 지도/사진의 기존 푸시 전환은 유지한다.
- 기능별 한국어 주석을 작성했다. React 검토 기준으로 훅 정리·접근성 이름·키보드 대체 조작·지연 응답 제외를 확인했다.

## 결과
- 최종 빌드(TypeScript/Vite) 통과, 단위 테스트142개 통과.
- 브라우저49개 통과: photo-place, location-confirm, live-session, location-search, back-flow. Chrome 설치 채널,360/390/430px·큰 글씨·동작 줄이기·취소/오류/뒤로가기·오래된 위치 재조회 포함. 검색/GPS/지도 SDK는 모의다.
- 실제 Tesseract 엔진+합성 한글 사진으로 첫째 줄만 선택해 은행 이름이 나오고 선택 밖 ATM은 나오지 않는 것을 확인했다. 합성 입력에서도 잡음 문자열은 남았다. 신뢰도 판정/현장 사진 개선 성공으로 해석하지 않는다.
- 원본4000×2500 화소 보존과 선택 영역1000×1000→테두리 포함1020×1020 출력을 실제 Canvas로 확인했다. 첫 실행은 JPEG 흰 테두리의 미세 손실(249,255,255)을 정확255로 가정한 검사1개가 실패했다. 제품 변경 없이 허용 범위를245 이상으로 바로잡고 최종49개를 재검증했다. 테스트용 동적 모듈 import의 타입 경로 오류도 수정 후 빌드를 재검증했다.
- 화면 자료는 합성 입력/모의 지도에서 생성했다. 사용자 영상·위치 프레임은 커밋하지 않는다. AI 지원 구현·검증.
- 원본 현장 사진이 없어 실패 재현/전후 인식률 비교는 못 했다. 실제 휴대폰 촬영·Samsung Internet·실외 GPS/도로 편 정확도는 미확인. OCR 품질 판정은 후속 작업이다. 커밋·푸시·배포 여부는 별도 기록한다.
