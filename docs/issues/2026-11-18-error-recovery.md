# 연속 오류 대응과 요청 대기 제한 (2026-11-18)

## 문제
기기 없이 수행 가능한 오류 대응 점검에서 검색·최초 경로·주소·설정 요청의 대기 시간이 제한되지 않은 점을 확인했다. HTTP 성공이라도 잘못된 경로나 장소 정보가 UI에 전달될 수 있고, null 오류 본문은 의도하지 않은 예외를 유발할 수 있었다.

## 원인
공통 요청 함수가 fetch/본문 읽기에 대기 제한을 두지 않고 응답 JSON을 TypeScript 형식으로만 간주했다. 사용자 취소와 본문 파싱 오류도 명확하게 구분하지 않았다.

## 해결방법
- 설정·검색·주소·경로의 네트워크/본문 읽기를 합쳐20초로 제한하고 재시도 안내를 제공한다.
- 기존 상위 취소 신호를 전달하며 완료/실패 시 타이머·취소 이벤트를 해제한다. 사용자 취소는 통신 실패로 표시하지 않는다.
- HTTP 성공도 설정 플래그, 장소 배열/좌표, 주소, 경로 거리·선분·안내 단계 형식을 검증한다. 잘못된 경로는 화면·기기 저장·기존 안내 교체에 사용하지 않는다.
- 통신 단절·본문 파싱 실패·서비스 오류·시간 초과를 구분하고 null/빈 오류를 안전한 사용자 문구로 바꾼다.
- 복원 중 권한 거절→통신 단절→서버 지연→잘못된 경로→재시도 성공을 한 흐름으로 검증한다. 기존 저장 안내와 GPS/카메라 시작 조건을 유지한다.

## 결과
단위133개·빌드 통과. 초기 설정 재시도 테스트가 실제 버튼명 ‘다시 시도’와 다른 이름을 찾는 오류를 수정했다. 최종 브라우저/배포 결과는 아래 추가한다. 모의 GPS·API·오류 주입 검증이며 실제 갤럭시 권한·실외 통신 조건은 미확인이다. API 제공자 정책/응답 구조는 이번에 변경하지 않았다. AI 지원 구현·검증·문서화.

로컬 검증: 브라우저45개 재실행 모두 통과(초기44/45 후 테스트 버튼명 수정). 추가로 선택 필드 category/entrance/roadName이 잘못된 경우도 응답 거부하도록 보완하고 단위133개·빌드 재통과. 단위는 헤더/본문 시간 초과·사용자 취소·통신 단절·잘못된 JSON·null 오류·잘못된 필드도 포함한다. 배포 후 연속 오류 재검증은 별도 기록한다.

배포 확인: 코드bd36e88의 Vercel 자동배포success. 공개 주소 https://gilbit.vercel.app 에서 연속 권한/통신/지연/잘못된 경로 후 복원 성공과 설정 지연 재시도2개 통과. 모의 GPS·API·오류 주입 검사이며 실제 갤럭시 실외 통신/권한 조건 검증과 구분한다.
