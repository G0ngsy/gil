# 모의 GPS 이동 추적 (2026-11-08)

## 문제
기존 실제 모드는 전체 경로 조회만 제공하고 이동에 따른 거리·단계·이탈·도착 판정이 없었다. Windows에서 `npm test`의 와일드카드가 확장되지 않아 테스트 파일도 찾지 못했다.

## 원인
GPS 좌표를 경로 선분에 투영하는 진행 상태 계산이 없었고, 테스트 명령이 셸의 파일 확장에 의존했다.

## 해결방법
- `/?mode=simulation`에 별도 모의 GPS 화면을 추가했다. 좌표 직접 입력 또는 출발·직진·회전·이탈·복귀·도착 버튼으로 좌표를 전달한다. 실제 검색 모드와 디자인 시안은 그대로 구분한다.
- `shared/tracking.ts`는 좌표를 가장 가까운 경로 선분에 투영해 경로 진행 비율로 남은 거리를 계산하고 단계 좌표를 지나면 자동 전환한다. 역방향 이동도 반영한다. 분리된 선분 사이에 가상의 연결선을 만들지 않는다.
- 경로와 35m 초과 떨어지면 이탈, 20m 이내로 돌아오면 복귀한다. 이탈 중 거리와 단계는 유지한다. 경로상 남은 길이와 종점 직선 거리가 모두 15m 이하이면 도착한다.
- 오차 30m 초과, 잘못된 좌표, 이전 시각의 좌표는 반영하지 않는다. 도착은 초기화 전까지 유지한다.
- Node 파일 목록 기반 실행기로 Windows 테스트 명령을 수정했다.

## 결과
- 검증: 단위 테스트 27개 통과, TypeScript 검사 및 프로덕션 빌드 통과.
- 브라우저 검증: 전체 36개 통과. 모의 이동·단계 전환·이탈·복귀·도착·부정확 좌표 거부·초기화 및 외부 경로 API 호출 없음 확인.
- 미확인: TMAP 키·실제 API·실기기 GPS 연동은 이번 작업 범위에서 보류했다. 실시간 위치 감시나 재탐색 API를 연결하지 않았다.
- 제한: 교차/중첩 경로는 가장 가까운 선분만 선택하므로 경로 순서 모호성이 있다. 임계값은 모의 검증용이며 현장 보정이 필요하다. 남은 거리는 제공된 총거리와 경로 형상 비율을 이용한 추정이다.

## 확인 방법
개발 서버를 실행한 후 `/?mode=simulation`으로 접속한다. 출발 → 직진 이동 → 회전 지점 → 다음 안내 → 경로 이탈 → 경로 복귀 → 도착 순서로 눌러 상태를 확인한다. 직접 입력한 위도·경도·오차도 같은 계산 경로를 사용한다. 추적 초기화로 다시 시작한다.
