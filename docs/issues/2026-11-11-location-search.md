# 현재 위치 주소 표시와 주변 장소 검색

## 문제
현재 위치를 받아도 확인 여부와 GPS 오차만 보여 실제 어디인지 알기 어려웠다. POI 검색에는 중심 좌표가 없어 전국 관련도순 결과가 표시됐고, 결과 거리도 현재 위치 변경과 검색 당시 기준이 섞일 수 있었다.

## 원인
브라우저 GPS 좌표를 주소로 변환하지 않았고 서버 POI 요청은 searchtypCd=A만 사용했다. 검색 결과의 기준 위치를 별도 보관하지 않았다.

## 해결방법
현재 위치 영역을 홈 검색창 아래 첫 영역으로 옮긴다. 버튼에서 GPS를 확인한 뒤 TMAP ReverseGeocoding으로 주변 주소를 표시한다. 주소·확인 시각·오차를 함께 보여 정밀 실시간 위치처럼 표현하지 않는다. 주소 실패 시 좌표는 유지하고 재시도할 수 있다. 새 위치 확인/컴포넌트 종료 시 이전 주소 요청을 취소하고 늦은 응답은 무시한다.

위치가 있으면 기본으로 중심 좌표·radius=10·searchtypCd=R을 요청한다. 서버에서도 10km 범위 밖 결과를 제외하고 직선 거리순으로 정렬한다. 거리와 기준 위치는 검색 시점의 표본으로 고정한다. 사용자가 전국 검색을 선택하면 중심 좌표를 전달하지 않고 기존 관련도순 검색을 사용한다. 위치 미확인은 전국 검색임을 명시하며, 주변 결과 없음 시 사용자 선택으로만 범위를 넓힌다. 2분 이상 지난 표본은 주변 검색 전에 갱신하며 실패 시 과거 좌표로 진행하지 않는다.

주소/주변 검색의 현재 좌표는 앱 서버에 POST 본문으로 전달해 브라우저 주소에 붙이지 않는다. TMAP REST 호출에서는 공식 GET 파라미터를 사용한다. 공급자 전달을 버튼 앞 문구와 개인정보 설명에 반영했다. 현재 좌표와 조회 주소는 앱 저장소에 기록하지 않으며 GPS 매 수신마다 주소 API를 호출하지 않는다.

## 검증 중 발견과 수정
추가한 오래된 위치 검증에서 부동소수점 덧셈의 37.567499999999995를 37.5675와 엄격 비교해 실패했다. 좌표 비교를 8자리 허용 비교로 변경했고 GPS 재요청 횟수와 새 좌표를 확인하는 조건은 유지했다. 제품 좌표를 임의 반올림하지 않았다.

## 결과
최종 검증/실제 배포 결과는 docs/validation-2026-11-11-location-search.md에 기록한다. 실제 휴대폰 GPS/실외 정확도는 별도 확인 대상이다. ReverseGeocoding 이용 권한/쿼터 실패는 주소 안내 오류로 처리하고 좌표/검색을 가짜 주소로 대체하지 않는다.

## 공식 근거

- [장소 통합 검색](https://tmap-skopenapi.readme.io/reference/%EC%9E%A5%EC%86%8C%ED%86%B5%ED%95%A9%EA%B2%80%EC%83%89): 거리순 R은 중심 위경도와 반경 필요, 반경 단위 km.
- [ReverseGeocoding](https://tmap-skopenapi.readme.io/reference/reversegeocoding): WGS84 좌표, A10 주소, newAddressExtend=N으로 확장 검색하지 않음.

## 배포 확인에서 발견한 설정 확인 경합

- 문제: 홈 직후 위치 버튼을 누른 원격 검증에서 주소 요청이 발생하지 않았다.
- 원인: configured=null(확인 중)과 false(미설정)를 함께 차단했다. 사용자 GPS 버튼을 누른 뒤에도 설정 응답보다 빠르면 주소 조회를 건너뛰었다.
- 해결방법: 확정된 미설정(false)일 때만 조회를 보류하고, 확인 중에는 사용자 동작에 따른 주소 요청을 서버로 보내 실제 응답을 처리한다. config 응답을 보류한 브라우저 회귀를 추가했다.
- 결과: 추가 회귀·최종 전체 실행 및 원격 재배포 결과는 검증 문서 참조.
